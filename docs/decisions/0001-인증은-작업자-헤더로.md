# 0001. 인증은 하지 않고, 작업자는 요청 헤더로 기록한다

- 날짜 / 관련 기능: 2026-10-22 / 전체 (특히 F2 상태 전이 이력의 actor)
- 상황: 상태 변경 이력에 "누가 바꿨는지"가 꼭 남아야 한다. 하지만 이 프로젝트의 목적은 Nest·MikroORM·MySQL·Redis 학습과 운영 흐름 구현이고, 기간은 7일이다.
- 선택지:
  1. JWT + 역할(운영자/관리자) — 실서비스에 가깝다 / 로그인·토큰 발급·Guard·역할별 권한 표까지 만들어야 해서 하루 가까이 든다. 학습 목표(ORM·큐·캐시)와 거리가 있다
  2. 요청 헤더 `X-Operator: 이름` — 이력에 작업자를 남기는 요구는 충족한다 / 누구나 아무 이름이나 넣을 수 있다(신뢰할 수 없음)
  3. 아무것도 기록하지 않음 — 가장 간단 / 이력의 핵심인 "누가"가 빠진다
- 결정: 2. 헤더가 없으면 400으로 거절한다. 배치·스캔 등 시스템이 바꾼 경우는 `system:<작업명>`으로 기록한다.
- 결과·대가: 인증·인가가 없다. 외부에 노출하면 안 되는 로컬 전용 서버로 둔다.
- 다시 볼 조건: 역할별 권한(예: 폐기 전이는 관리자만)이 필요해지면 1로. 헤더를 읽는 부분을 한 곳(데코레이터/미들웨어)에 모아 두면 교체 비용이 작다.
