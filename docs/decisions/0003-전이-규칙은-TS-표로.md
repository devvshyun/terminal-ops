# 0003. 전이 규칙을 TS 표 + 순수 함수로 둔다

- 날짜 / 관련 기능: 2026-10-22 / F2
- 상황: 모델마다 전이가 조금씩 다르다(SN-200은 회수 후 재검수 필수). 검수 전이는 검수 기능으로만 일어나야 한다.
- 선택지:
  1. YAML 파일 — 이전 프로젝트에서 쓴 방식. 코드와 분리되지만 타입 검사가 없다.
  2. TS 표 + 순수 함수 — 타입 검사와 단위 테스트가 쉽다. 규칙을 바꾸려면 배포가 필요하다.
  3. DB 테이블 — 운영자가 바꿀 수 있지만 지금은 필요 없다.
- 결정: 2. 이유: 상태 enum을 타입으로 검사받고, DB 없이 단위 테스트로 모든 전이를 확인할 수 있다.
- 규칙: `only`로 전이 경로를 제한하고, `blockedBy`로 모델 정책을 적용한다. 같은 상태로의 전이는 표에 없으므로 자동으로 거절된다.
- 결과·대가: 규칙을 바꾸려면 코드를 고치고 배포해야 한다.
- 다시 볼 조건: 운영자가 규칙을 직접 바꿔야 하면 3으로.

- 주의: `only`가 없는 규칙은 INSPECTION을 뺀 모든 출처를 허용한다. 이후 BATCH·SCAN·IMPORT 같은 출처를 추가하면 그 출처가 모든 일반 전이에 자동으로 허용된다. 출처를 추가하는 날 규칙별 허용 범위를 다시 정한다(기본값을 MANUAL만으로 좁히는 안 포함).
- 갱신(2026-10-22 Day 2): BATCH 출처를 추가하면서 기본 허용 출처를 MANUAL로 좁혔다 → decisions/0007
