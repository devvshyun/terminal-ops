# 0030. 펌웨어 단계 배포는 별도 테이블과 Redis 제안으로

- 날짜 / 관련 기능: 2026-10-23 / F8 (Day 4 Task 6)
- 상황: F8은 "펌웨어 10% → 50% → 100% 단계 배포, 실패율이 높으면 자동 중단"이다. 단말기는 하트비트로만 서버와 이야기한다(서버가 단말기를 부르지 않는다). 설계안의 SN-300은 펌웨어가 잦다.
- 선택지(모델):
  1. 단말기 상태 enum에 UPDATING 같은 값을 더하기. 펌웨어 업데이트는 생애주기가 아니다(설치된 채로 진행된다). enum ALTER와 전이 규칙만 커진다(Day 3 리뷰의 Day 4 준비 메모).
  2. **별도 테이블 3개**(`firmware`, `firmware_rollout`, `firmware_rollout_target`). 배포 진행과 단말기별 결과를 따로 가진다. 단말기 enum은 그대로다.
- 결정: 2.
- 대상 선정: 그 모델의 IN_SERVICE 단말기를 `crc32(serial_no), id` 순으로, 단계마다 **누적** 비율만큼 고른다(모수 = 이미 대상 + 아직 대상 아닌 운영 중 단말기, `ceil`).
  - 같은 단말기 목록이면 늘 같은 순서다. 재현과 테스트가 된다(Node `zlib.crc32`가 MySQL `crc32`와 같은 값). 시리얼 앞부분(발주번호)에 몰리지 않는다.
  - 버린 것: 무작위(`RAND()`)는 재현이 안 된다. id 순은 오래된 단말기에 몰린다.
- 제안 전달:
  1. 하트비트마다 MySQL에서 OFFERED 대상을 조회. decisions/0027(하트비트는 Redis에만)을 깬다.
  2. **Redis HASH `fw:offers`(serialNo → {rolloutId, version}) 사본.** 하트비트 첫 왕복(pipeline)에 HMGET 하나를 더한다. 원본은 대상 행(OFFERED)이다.
  - → 2. 사본은 **커밋 뒤** 건다(롤백된 배포의 제안이 남지 않게). 걸기 전에 죽으면 그 단계 대상은 제한 시간 뒤 TIMED_OUT(Task 7)이 된다.
- 제안 내리기: 배포 id가 같을 때만 지우는 Lua(`cjson.decode`)로 한다. 중단된 배포의 늦은 삭제가 같은 단말기에 새로 생긴 다른 배포의 제안을 지우지 않게 한다.
- 모델당 진행 중(RUNNING·PAUSED) 배포는 하나: 만들 때 `terminal_model` 행을 FOR UPDATE로 먼저 잡고 센다. 잠근 뒤에 센 수라야 동시에 둘이 생기지 않는다(decisions/0023의 "열린 접수는 하나"와 같은 방식). 테스트: 동시 2건 → [201, 409], 3번 돌려 3번 같음.
- 멈춤·재개·중단: 배포 행을 FOR UPDATE로 잡는다.
  - 멈춤은 제안을 내린다(이미 받은 단말기의 보고는 계속 받는다).
  - 재개는 OFFERED 대상의 offered_at을 지금으로 PK 갱신하고(멈춘 시간을 제한 시간에 넣지 않음) 제안을 다시 건다.
  - 중단은 ABORTED + Outbox `firmware.rollout_aborted`. 단계 시작·완료 type(`firmware.stage_advanced`, `firmware.rollout_completed`)과 문구도 미리 넣었다(쓰는 곳은 Task 7).
  - version 컬럼은 두지 않는다(모든 변경이 FOR UPDATE 아래).
- 결과·대가:
  - 대상 행 INSERT의 FK 검사가 단말기 행 수백 개에 S 락을 건다. 이 트랜잭션은 단말기 행을 바꾸지 않아 S→X 승격은 없다. 다만 같은 단말기를 전이하는 트랜잭션(X 락)은 배포 만들기가 커밋할 때까지 기다린다.
  - 이미 그 버전인 단말기도 대상이 된다(업데이트 없이 성공 보고하면 된다, 지금은 빼지 않음).
  - 재개와 보고가 겹치면 이미 보고한 단말기에 제안이 다시 걸릴 수 있다. 그 단말기가 다시 보고하면 보고 API가 제안을 내린다(Task 7, 멱등).
  - 하트비트 응답 크기: 제안이 있는 행에만 `update`가 붙는다. 하트비트 왕복 수는 그대로 2번이다(조회 pipeline에 HMGET 하나 추가).
- 다시 볼 조건: 여러 모델을 한 번에 배포해야 할 때, 대상이 수만 대가 되어 단계 진입 INSERT가 무거워질 때, 특정 가맹점·지역부터 배포해야 할 때(선정 규칙 교체).
