# 0037. 알림·리포트 레이블을 상수 파일로

- 날짜 / 관련 기능: 2026-10-27 / F4, F5, F9, F11 (Day 5 최종 리뷰 Minor 5)
- 상황: `outbox.service.ts`와 `weekly-report.xlsx.ts`가 문구 레이블(`ANOMALY_RULE_LABEL`, `KIND_LABEL`) 때문에 `anomaly-rules.ts`(env, DB 쿼리 함수)와 `van-compare.ts`(비교 로직)를 import했다. 순환은 없지만 알림·리포트(아래층)가 도메인 로직(위층)에 기댄다. 어드민 화면도 같은 이름이 필요해졌다(Task 3이 API로 준다).
- 선택지:
  1. 그대로 — 지금은 문제 없음. 규칙 파일이 무거워지면(쿼리·외부 호출) outbox를 불러오는 모든 곳이 끌려온다.
  2. 레이블을 outbox로 옮김 — 리포트·API도 outbox에 기대게 된다.
  3. **enum만 import하는 상수 파일(`src/anomaly/anomaly-labels.ts`, `src/van/van-labels.ts`)**
  4. 레이블을 DB 표로 — 바뀔 일이 없는 이름에 과함.
- 결정: 3. import 문을 읽는 단위 테스트(`test/unit/module-deps.spec.ts`)가 outbox·xlsx가 규칙·비교 파일을 다시 import하면 실패한다. 레이블 파일은 enum 파일만 import한다(같은 테스트가 확인하고, 레이블 키가 enum 값 순서와 같은지도 본다).
- 결과·대가: 규칙을 더하면 enum·레이블·규칙 세 곳을 고친다(`Record<AnomalyRule, string>` 타입이라 레이블을 빠뜨리면 컴파일 오류). import 검사는 정규식(`from '...'`)이라 동적 import나 다시 내보내기(re-export)를 거친 의존은 잡지 못한다.
- 다시 볼 조건: 이름을 운영자가 바꿔야 하면 4.
