# 0041. 어드민 골격 — Vite 프록시, 작업자 헤더, 프런트 도구

- 날짜 / 관련 기능: 2026-10-27 / 어드민 전체(설계안 4장 "어드민 화면 (React)", 6장 `apps/admin`)
- 상황: 브라우저가 api(3000)를 부르는 방식, `X-Operator`(decisions/0001)를 사람이 쓰는 화면에서 넣는 방식, 프런트 도구·버전, 스타일을 정해야 한다. Day 5 리뷰 이월 "Day 6 준비".
- 선택지(출처)
  1. api에 CORS 열기(`app.enableCors`) — 운영에서도 열어야 하는지, 허용 출처 관리가 생긴다.
  2. **Vite 개발 서버 프록시(`/api` → 3000, rewrite로 앞의 `/api`를 뗌)** — 같은 출처라 CORS가 필요 없다. 운영은 같은 모양의 역프록시(범위 밖).
  3. api가 정적 파일까지 서빙 — 빌드 결과를 api에 묶는다.
- 선택지(작업자)
  1. 요청마다 입력 — 번거롭고 빠뜨린다.
  2. **위쪽 입력 → localStorage(`terminal-ops.operator`) → `api()`가 모든 요청에 `X-Operator: encodeURIComponent(이름)`**(비면 쓰기 버튼 끔). 저장소 구독은 `useSyncExternalStore`(Provider 없음). 규칙은 서버와 같다(1~50자, `system:` 금지).
  3. 로그인 — 인증은 범위 밖(decisions/0001).
- 선택지(도구)
  - 화면: React 19 + Vite(설계안).
  - 라우터: **react-router 8(선언형 `Routes`/`Route`)** — 데이터 라우터의 loader·action은 TanStack Query와 겹쳐 쓰지 않는다. TanStack Router(타입 경로)는 화면 11개에 과하다. `react-router-dom` 없이 `react-router` 하나에서 `BrowserRouter`·`MemoryRouter`·`NavLink`를 가져온다.
  - 서버 상태: **TanStack Query**(캐시·무효화·무한 목록). 직접 `useEffect` + `fetch`는 로딩·오류·다시 읽기를 화면마다 다시 짠다. SWR은 무한 목록·변이 API가 약하다. 기본값: 4xx는 재시도 안 함(연결 실패·5xx만 한 번), 창 포커스 때 다시 읽지 않음, staleTime 5초.
  - 테스트: **Vitest + Testing Library + jsdom**(api와 같은 Vitest). Playwright는 브라우저 내려받기가 필요해 이번엔 쓰지 않는다(실제 화면은 컨트롤러가 내장 브라우저로 본다). 가짜 api는 `fetch`를 `vi.stubGlobal`로 바꾸는 `mockApi`(경로 패턴, 부른 요청 기록, 없는 경로는 404).
- 선택지(스타일)
  1. **전역 CSS 한 장**(색은 변수).
  2. CSS Modules — 화면이 작아 클래스 충돌이 없다.
  3. Tailwind·UI 라이브러리 — 의존성·설정이 늘고 학습 범위 밖.

### Task 5 보탬 (단말기 화면)
- 목록 조건은 주소에(`useSearchParams`) — 뒤로 가기·새로고침·링크 공유가 같은 목록을 보여 준다. 입력 중인 값은 상태(draft), 검색 버튼을 눌러야 주소가 바뀐다(타자마다 요청하지 않는다).
- 쓰기 뒤에는 응답으로 화면을 고치지 않고 관련 쿼리를 무효화해 다시 읽는다(응답 모양이 API마다 달라도 화면은 상세 하나만 믿는다). 낙관적 갱신은 하지 않는다(전이 결과는 서버 규칙·version이 정한다).
- version 충돌은 자동으로 다시 보내지 않는다 — 다른 사람이 무엇을 바꿨는지 운영자가 보고 다시 판단한다(decisions/0004).

### Task 4 리뷰 반영 (탭 간 동기화·재시도 판정)
- 작업자 이름은 `window`의 `storage` 이벤트를 구독해 다른 탭의 변경을 따라간다(처음 결정은 "탭마다 따로"였고 대가에 적었다 — 한 탭에서 이름을 바꿔도 다른 탭의 쓰기가 옛 이름으로 나가 이력이 어긋나는 일을 막으려고 바꿨다). 이벤트의 `key`가 이 키이거나 `null`(저장소 전체 비움)일 때만 저장소에서 다시 읽고, 규칙에 어긋난 값이면 빈 이름이 된다. 버린 선택지: 탭 간 불일치를 대가에 한 줄 적고 두기(구현은 7줄이고 이력의 작업자가 틀리는 쪽이 더 비싸다).
- (최종 리뷰 Minor 8 반영) 위쪽 입력칸(`OperatorBar`)도 바뀐 이름을 따라간다. 고치는 중(입력이 마지막으로 맞춘 이름과 다름)이면 덮어쓰지 않고 "지금: …" 표시만 바뀐다. 렌더 중에 `synced`와 비교해 맞춘다. 버린 선택지: `useEffect(() => setDraft(operator))`(한 번은 옛 값으로 그리고, 고치는 중인 입력도 지운다), `key={operator}`(다시 마운트로 고치는 중인 입력과 오류 표시가 사라진다).
- 조회 재시도 판정을 `shouldRetry(count, error)`로 빼 단위 테스트한다(4xx 안 함, 5xx·연결 실패 한 번).
- 이름 입력칸 `maxLength`는 서버 규칙과 같은 50(60이면 51~60자를 쓰게 두고 저장 때 막는다).

### Task 6 보탬 (박스 스캔)
- scanId는 화면이 박스마다 만들고(`crypto.randomUUID`) 결과를 받을 때까지 지킨다 — 다시 보내기가 서버의 멱등(decisions/0020)을 그대로 쓴다. 다시 보낼지 고칠지는 오류 종류로 가른다(처리 중 409 `SCAN_IN_PROGRESS`·5xx·연결 실패는 같은 scanId, 4xx 입력 오류는 새 scanId). 보낸 박스의 목록을 잠가(readOnly) "같은 scanId에 다른 내용"(422 `SCAN_ID_REUSED`)을 화면에서 만들지 않는다.
- 버린 선택지: 오류마다 scanId를 새로 만들기(응답만 못 받은 경우 서버에서 이미 처리됐는데 새 scanId로 또 보내 같은 박스가 두 번 처리되어 멱등을 깬다), 보낸 뒤에도 목록 편집 허용(SCAN_ID_REUSED를 운영자가 만나게 된다).

### Task 5 리뷰 보탬 (목록 입력칸과 주소)
- 목록의 검색 조건은 주소가 진실이고 입력칸(draft)은 제출 전 임시값이다. 뒤로/앞으로 가기로 주소의 조건이 바뀌면 `useEffect`로 draft를 주소 값에 맞춘다. 쪽 번호만 바뀔 때는 draft를 건드리지 않게 조건 값만 키로 본다(쪽 넘기다 입력하던 검색어가 사라지지 않게).
- 버린 선택지: 목록을 `key={주소}`로 통째로 다시 마운트(쪽을 넘길 때마다 keepPreviousData 화면이 깜빡이고 draft도 잃는다), 입력칸이 주소를 직접 쓰기(글자마다 요청·히스토리가 쌓인다).
- 고른 전이는 상태로 들고 있되, 화면에는 새로 읽은 `allowedTransitions`에 있고 막히지 않은 것만 쓴다(파생값). 서버 쪽 규칙을 화면에 복제하지 않는다는 decisions/0040과 같은 방향.

### Task 7 보탬 (더 보기 목록, 확인 대화상자)
- "더 보기" 목록은 `useInfiniteQuery` 하나(`api/lists.ts`) — 쪽 번호가 없는 키셋 API(decisions/0039)와 모양이 같다. 쪽마다 따로 캐시하고 화면이 이어 붙인다. 조건(상태 필터)이 queryKey에 들어 있어 조건이 바뀌면 처음부터 읽는다.
- 되돌릴 수 없는 일(배포 중단, 발주 마감)만 `window.confirm`으로 한 번 더 묻는다. 멈춤·재개처럼 되돌릴 수 있는 것에는 묻지 않는다.
- A/S·배포의 버튼은 상태 값으로 고른다(규칙이 상태 하나에 1:1이고 서버가 다시 검사해 422로 알려 준다). 단말기 전이처럼 서버가 가능한 일을 계산해 주지는 않는다.

### Task 6 리뷰 보탬 (박스 스캔)
- "새 박스"는 보내는 중이면 꺼지고, 보냈는데 결과를 못 받은 박스(scanId는 있고 결과 없음)를 버릴 때는 `window.confirm`으로 묻는다 — 서버가 이미 처리했을 수 있는데 scanId를 버리면 같은 scanId로 저장된 결과를 받아 볼 길이 없어진다. 늦게 온 오류 응답은 요청한 scanId가 지금 박스의 것일 때만 scanId를 지운다(ref 비교, UI로는 보내는 중 새 박스가 꺼져 있어 방어용).
- 409 `VERSION_CONFLICT`(회수 박스를 처리하다 다른 작업과 겹쳐 박스 전체가 롤백)도 같은 scanId로 다시 보내는 쪽으로 분류한다. 서버가 결과를 저장하지 않았으니 같은 내용으로 다시 보내면 처음부터 처리한다. 버린 선택지: 안내 문구만 바꾸기(이 화면에는 "다시 불러올" 데이터가 없어 운영자가 할 일은 결국 다시 보내기다).
- 열린 발주는 `?status=ORDERED`·`?status=RECEIVING`을 각각(limit 100) 불러 id 내림차순으로 합친다. 버린 선택지: 최근 100개를 받아 CLOSED를 거르기(마감된 발주가 100개 넘게 쌓이면 오래된 열린 발주가 목록에서 잘린다), "더 보기"로 끝까지 읽기(선택 상자에 필요 없는 CLOSED까지 읽는다). 열린 발주가 상태별 100개를 넘는 경우는 잘린다(대가 — 그 규모면 검색 입력으로 바꾼다).
- 스캔이 성공하면 `['purchase-orders']`도 무효화한다(입고로 ORDERED → RECEIVING, 발주 대조 화면의 수가 바뀐다).

### Task 8 보탬 (리포트 화면, 202 작업 다시 읽기)
- 202 작업(VAN 대조, 주간 리포트 보내기)은 화면이 2초마다 다시 읽는다(`RunningPoller`). 진행 중인 것(VAN `RUNNING`, 주간 리포트 `queued`)이 목록에 보일 때만 그려져 돌고, 다시 읽은 목록에서 사라지면 컴포넌트가 빠져 타이머가 멈춘다. 웹소켓·SSE는 쓰지 않는다(decisions/0038과 같은 이유 — 운영자 몇 명이 가끔 보는 화면이고 결과는 DB 행에 남는다). 버린 선택지: TanStack Query `refetchInterval`을 함수로(조건과 화면 표시 "다시 읽는 중"이 두 곳으로 갈라진다).
- 내려받기는 `<a href="/api/…/file" download>` — 브라우저가 프록시로 바로 받는다(GET이라 작업자 헤더가 필요 없다).
- 주간 리포트가 대기열에 있는 동안(`queued`)은 `lastError`를 숨긴다 — 지난 시도의 오류라 지금 보내는 중인데 실패처럼 보인다. 대신 `queuedAt` 기준 "N분째 대기(KST 시각부터)"를 보이고, 10분(`WORKER_HINT_AFTER_MIN`) 넘게 대기면 "워커가 실행 중인지 확인" 안내를 띄운다(decisions/0038의 운영 전제: 워커가 없으면 job이 waiting에 남는다). 기준 시각은 브라우저 지금이 아니라 마지막으로 읽은 시각(`dataUpdatedAt`)으로 둔다 — 화면 숫자가 서버를 읽은 시점과 맞는다. 버린 선택지: 화면에 따로 1분 타이머(대기 중에는 이미 2초마다 다시 읽는다), 대기 중에도 lastError를 흐리게 보이기(실패로 읽힌다).
- 10분 기준은 화면 상수다. 서버는 기준 없이 `queuedAt`만 준다(운영 판단은 화면 쪽 문구라서). 바꿀 조건: 보내기 한 번이 10분 가까이 걸리게 될 때(첨부·수신자가 커질 때).

### Task 7 리뷰 보탬 (A/S·배포 쓰기 실패)
- 쓰기가 실패하면(422 `TICKET_NOT_OPEN`·`ROLLOUT_NOT_RUNNING`·`TERMINAL_NOT_IN_STOCK` 등) 오류 안내는 그대로 두고 관련 조회를 무효화해 서버 상태를 다시 읽는다(A/S 상세 `onError`, 배포 제어 `onSettled`). 이 두 화면의 422는 대개 "다른 운영자가 먼저 바꿨다 = 화면이 낡았다"는 뜻이다. Task 5의 `ErrorBox onReload`("다시 불러오기" 버튼)는 409 VERSION_CONFLICT에만 나오는데, A/S·배포는 version 없이 상태로 막으므로 409가 아니라 422가 온다. 버린 선택지: 422마다 "다시 불러오기" 버튼(운영자가 눌러야만 낡은 화면이 바뀌고, 누를 이유는 항상 같다).
- 교체 단말기 선택은 저장한 값이 아니라 "다시 읽은 재고 목록에 있는 값"으로 파생한다(`chosen`). 재고에서 빠진 단말기를 계속 선택한 채 버튼이 켜져 있으면 다시 보내도 같은 422가 난다. 버린 선택지: 목록이 바뀔 때 effect로 상태를 비우기(렌더 뒤 한 박자 늦게 비워져 그 사이 버튼이 켜진다).
- 재고 후보는 50대까지만 받으므로 `total`이 더 크면 "N대 중 최근 M대만 표시"를 보인다. 검색 입력은 만들지 않았다(교체 후보는 최근 등록 순이면 충분한 규모).

### Task 9 보탬 (배치 실행 이력)
- 탭 상태는 `useState`가 아니라 주소(`?tab=`)에 둔다 — 새로고침·링크 공유·뒤로 가기에서 같은 탭이 남는다. 버린 선택지: 탭마다 경로(`/batch-runs/sync` …, 라우트가 셋으로 늘고 "이력" 하나의 메뉴 항목과 맞지 않음), `useState`(새로고침하면 첫 탭으로 돌아온다). 모르는 `tab` 값은 오류 대신 첫 탭.
- (최종 리뷰 Minor 1 반영) 택배 수집 조건(`?job=&outcome=`)도 주소에 둔다 — 단말기 목록과 같게, 뒤로 가기·새로고침에서 조건이 남는다. 탭을 바꾸면 `?tab=`만 남기고 조건은 버린다: 조건은 택배 수집 탭에만 있고, 다른 탭에서 돌아왔을 때 보이지 않던 조건이 걸려 있으면 헷갈린다(되돌리려면 뒤로 가기). 버린 선택지: 지역 상태(탭을 바꾸면 언마운트로 말없이 사라지고 새로고침에도 사라진다).
- (최종 리뷰 Minor 1 반영) VAN·주간 리포트 탭도 진행 중(RUNNING·대기열)이면 `RunningPoller`로 2초마다 다시 읽고 "새로고침" 버튼을 둔다. 두 탭은 VAN·주간 리포트 화면과 캐시 키를 공유해서, 거기서 넘어오면 낡은 "대기열"이 그대로 남았다. 주간 리포트 목록 쿼리는 `api/lists.ts` `useWeeklyReports()` 하나로 모았다(같은 키에 다른 queryFn이 붙지 않게). 행 링크는 `/reports/weekly?week=<주>` — 주간 리포트 화면이 그 주를 보낼 주 입력의 처음 값으로 받고 행을 `aria-current`로 표시한다.
- 배치 실행 이력은 실행 기록이 있는 셋만 보인다. 이상 단말기 찾기는 실행 기록 표를 만들지 않았으므로(decisions/0038·0039) 화면에 그 사실을 한 줄로 적어 "이력이 없다 = 안 돌았다"로 읽히지 않게 한다.

### Task 8 리뷰 보탬 (다시 읽기와 보낼 주 입력)
- `RunningPoller`는 `refetch({ cancelRefetch: false })`로 부른다. 설치된 `@tanstack/query-core` 5.104.2의 `queryObserver.fetch`는 `cancelRefetch: fetchOptions.cancelRefetch ?? true`이고, `query.fetch`는 데이터가 있고 `cancelRefetch`이면 진행 중인 요청을 `cancel({ silent: true })`한다. 그래서 응답이 2초보다 늦으면 폴링마다 앞 요청을 버리고 새로 불러 결과가 영영 반영되지 않는다(테스트로 확인: 3초 응답에서 `보내는 중` 표시가 사라지지 않음). `false`면 진행 중인 요청의 promise를 그대로 기다린다. 버린 선택지: `isFetching`이면 건너뛰기(같은 효과인데 호출하는 쪽마다 `isFetching`을 넘겨야 한다). 운영자가 직접 누르는 "새로고침" 버튼은 기본(취소 후 새로)대로 둔다.
- 주간 리포트 보낼 주 입력은 `max=지난주 월요일`, 월요일이 아니거나 그 뒤면 보내기를 끄고 이유를 보인다(`weekStartProblem`). 서버도 422 `WEEK_NOT_ENDED`·400으로 막지만 운영자가 누르기 전에 알 수 있게. 버린 선택지: 주 선택을 드롭다운(최근 N주)으로(오래된 주를 다시 보낼 때 막힌다).
- VAN 대조 상세는 실행 번호를 `key`로 둬서 번호가 바뀌면 필터(종류·재검증)를 처음 값으로 되돌린다. 버린 선택지: `useEffect`로 id가 바뀔 때 상태 비우기(한 번은 이전 필터로 새 실행을 부른다).
- 409 `VAN_RECONCILIATION_RUNNING`·`ANOMALY_SCAN_RUNNING`은 `ErrorBox`가 "이미 진행 중인 작업이 있습니다" 안내를 붙인다(서버 메시지·코드는 그대로).

### Day 7 보탬 (쿼리 키 팩토리 — Day 6 최종 리뷰 Minor 4)
- 키는 `src/api/query-keys.ts`의 `keys`에서만 만든다. 첫 칸이 무효화 단위다: 목록 묶음은 복수(`terminals`, `purchase-orders`, `service-tickets`, `van-runs` …), 한 건 묶음은 단수(`terminal`, `purchase-order`, `service-ticket`, `van-run`). 둘은 다른 키라 한쪽을 무효화해도 다른 쪽은 남는다 — 쓰기 뒤에는 바뀐 것을 보여 주는 묶음을 **모두** 무효화한다. 글자는 Day 6과 같게 두어 캐시 동작은 아래 두 곳만 바뀌었다.
- 빠졌던 무효화: 박스 스캔 성공 → `keys.terminal.all`(스캔한 단말기들의 상세)·`keys.purchaseOrder.all`(입고 대조), A/S 교체 출고·설치 확인 → `keys.terminal.all`(고장·교체 단말기 상세). 지금까지는 staleTime 5초와 마운트 때 다시 읽기 덕분에 드러나지 않았다.
- 화면 소스에 `queryKey: [` 글자가 생기면 `query-keys.test.ts`가 실패한다(소스를 `import.meta.glob(…, { query: '?raw' })`로 읽음). "더 보기" 목록 키는 `keysetKey(묶음, 조건)`.
- 버린 선택지: 키 글자를 단수로 통일(`terminal`) — 목록과 한 건이 한 번에 무효화되지만 상세 화면이 목록 쓰기마다 다시 읽고, 기존 테스트의 키(`['terminals', 'probe']`)가 다 바뀐다. `@lukemorales/query-key-factory` 같은 라이브러리 — 새 의존성, 이 정도 크기에는 객체 하나면 된다.
- 409 `DEADLOCK`(api decisions/0043)은 ErrorBox가 "잠시 뒤 다시 시도"로 안내한다.
- 처음 화면은 운영 현황 카드(api decisions/0044). 서버가 30초 캐시하므로 화면은 `cachedAt`을 "YYYY-MM-DD HH:mm:ss KST 기준 (N초 전)"으로 보여 주고, 새로고침은 `?refresh=true` 응답을 `setQueryData`로 그대로 넣는다(읽기 결과라 무효화 대신 — 무효화하면 캐시된 값을 다시 받는다). 카드는 `<section aria-labelledby={useId()}>`.

### 보강 2 보탬 (로그인 — api decisions/0050·0052·0056)
- 작업자 이름 입력(`OperatorBar`, `operator.ts`, localStorage `terminal-ops.operator`)과 `X-Operator` 헤더를 지웠다. 로그인은 서버 세션 쿠키(httpOnly)라 화면 JS가 토큰을 다루지 않는다 — `api()`는 인증 헤더를 붙이지 않고, 같은 출처(Vite 프록시)라 브라우저가 쿠키를 붙인다.
- `session.ts`는 `GET /auth/me` 결과만 기억한다(undefined = 모름, null = 로그인 안 함). localStorage에 두지 않는다 — 새로 열면 서버에 다시 묻는다. 저장소 구독은 작업자 이름 때와 같은 `useSyncExternalStore`.
- `AuthGate`가 로그인해야 보이는 화면들을 감싼다: 모르면 `/auth/me`, 401이면 `/login`으로(돌아올 주소를 state로), 가맹점주면 안내와 로그아웃만. 어떤 요청이든 401(로그인 요청 자체 빼고)이면 `api()`가 내 정보를 비워 로그인 화면으로 간다. 로그아웃은 쿼리 캐시를 비운다(다음 사람이 앞사람 데이터를 보지 않게).
- 메뉴(`nav.ts`의 `roles`)와 쓰기 버튼(`WriteButton roles`, 기본 운영자)은 역할이 아니면 숨긴다. 서버가 최종 판단하고, 403 `FORBIDDEN`은 ErrorBox가 "권한이 없습니다"로 안내한다. 현장 작업자의 처음 화면은 박스 스캔.
- 버린 선택지: 내 정보를 TanStack Query로(`useQuery(['me'])`) — 모든 쓰기 버튼이 쿼리를 구독해 화면 테스트마다 `/auth/me` 가짜 응답이 필요해진다(지금 테스트는 `loginAs()` 한 줄). 쓰기 버튼을 역할 밖에서도 꺼진 채 보이기 — 브리프의 "숨김"과 다르고, 할 수 없는 일을 화면이 늘어놓는다.
- 한계(보강 2 마감, Task 3·어드민 리뷰): **다른 탭에서 사용자가 바뀌면 이 탭은 알아채지 못한다.** 같은 브라우저라 쿠키(`sid`)는 하나라, 다른 탭에서 로그아웃 뒤 다른 아이디로 로그인하면 이 탭의 다음 요청은 새 사람의 세션으로 나가지만 화면의 내 정보·메뉴·캐시는 앞사람 것이다(서버가 새 사람의 역할로 판단하므로 권한이 새는 것은 아니고, 화면 표시와 이력 actor가 어긋나 보일 수 있다). 탭 포커스 때 `/auth/me` 다시 묻기, `BroadcastChannel`·`storage` 이벤트로 탭끼리 알리기는 이월(계정 관리 화면과 함께 Bundle 7에서 본다). 로그아웃 뒤 이 탭의 다음 요청은 401이라 로그인 화면으로 간다.
- 사람이 바뀔 때 캐시를 비우는 순간 이미 나가 있던 요청의 응답은 새 캐시에 들어가지 않는다(TanStack Query `clear()`가 쿼리를 빼낸 뒤라 빠진 쿼리에 쓰인다) — 의도한 동작이다(`SessionCacheSync.tsx` 주석).
