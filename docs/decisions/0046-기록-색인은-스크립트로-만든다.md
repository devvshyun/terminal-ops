# 0046. 기록 색인(docs/index.md)은 스크립트로 만들고 --check로 확인한다

- 날짜 / 관련 기능: 2026-10-27 / 기록(CLAUDE.md 기록 규칙)
- 상황: 7일 동안 결정 46·트러블슈팅 28·실험 16개가 쌓였다(Day 7 끝 기준). 폴더를 열어 파일 이름을 훑는 것 말고 제목을 한 번에 볼 곳이 없다. README와 회고가 기록을 링크해야 한다.
- 선택지:
  1. 손으로 쓴 색인 — 장점: 도구 없음, 설명을 덧붙일 수 있다. 단점: 기록을 더할 때마다 잊는다. 이미 계획 문서의 번호 착오(계획 단계 번호가 남은 참조, Day 6 Minor 2)처럼 손으로 맞춘 목록은 어긋난다.
  2. 스크립트로 만든 색인 + `--check` — 장점: 파일 첫 줄 제목이 유일한 원본, 어긋나면 `--check`가 exit 1. 단점: 설명은 붙일 수 없다(제목만). 스크립트 하나를 관리한다.
  3. 색인 없이 README에 폴더 링크만 — 단점: 제목을 보려면 파일을 하나씩 연다.
- 결정: 2. `node scripts/docs-index.mjs`(node 내장 모듈만, 의존성 없음)가 `docs/{decisions,troubleshooting,experiments}/NNNN-*.md`의 첫 줄 `# NNNN. 제목`을 번호 순서로 `docs/index.md`에 쓴다. 파일 이름이 NNNN-으로 시작하지 않거나 첫 줄 번호가 이름과 다르면 멈춘다(양식 검사도 겸한다). `--check`는 다시 만든 내용과 지금 파일이 다르면 exit 1 — 마감 검증(Task 9)에 넣는다. 색인에 설명이 필요하면 README의 결과 표·회고에 쓴다.
- 결과·대가: 기록을 더한 커밋에서 스크립트를 다시 돌려야 한다(잊으면 `--check`가 잡는다 — 지금은 사람이 돌린다. git hook·CI는 두지 않았다). `--check`는 줄바꿈(CRLF·LF) 차이는 무시한다(Windows 체크아웃에서 git이 CRLF로 바꿔도 통과).
- 다시 볼 조건: CI를 붙이면 `--check`를 CI에 넣는다. 제목 외에 상태(채택·폐기)를 보여 줘야 하면 머리글 필드를 정해 스크립트가 읽는다.
