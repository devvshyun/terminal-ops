# 0070. 화면 디자인은 CSS 토큰으로 다듬고, 글꼴은 앱에 넣는다(현장 앱부터)

- 날짜 / 관련 기능: 2026-10-29 / 현장 화면(`apps/field`, 보강 4), 이어서 매장·어드민
- 상황: 세 화면 앱(어드민·매장·현장)은 기능은 갖췄지만 모양이 GitHub 기본 색(#1f2328·#0969da·#1a7f37)에 시스템 글꼴이고, 카드가 모두 같은 무게라 무엇이 중요한지 안 보인다. 현장 앱은 초록 버튼 두 개가 같고, 박스 스캔에서 거절된 줄은 작은 빨간 테두리 이름표로만 보여 100줄 박스에서 찾기 어렵다. 넓은 화면(사무실 PC, 포트폴리오를 여는 면접관)에서는 560px 한 줄이 빈 바탕 가운데 떠 있다. 시안은 HTML 페이지로 먼저 만들어 지금 화면과 나란히 비교했다(아티팩트 "단말온 화면 시안", 2026-10-29).
- 선택지:
  1. **UI 라이브러리 없이 전역 CSS 한 장을 토큰(색·글꼴 변수)으로 다시 쓴다** — 0041·0057·0061의 "전역 CSS 한 장"을 지킨다. 테스트가 보는 글자·구조(링크 이름 "박스 스캔", `3개` 같은 숫자 글자, `.serial`)를 그대로 둘 수 있다
  2. Tailwind 등 도구를 들인다 — 클래스가 마크업으로 옮겨 와 거의 모든 TSX가 바뀐다. 세 앱이 복사 구조(0058·0062)라 셋 모두에 설정이 생긴다. 얻는 것(일관된 간격 단위)은 토큰으로도 된다
  3. 컴포넌트 라이브러리(MUI 등) — 번들이 커지고 PDA 화면에 맞추려면 덮어쓰기가 많다. "라이브러리 기본 모양"으로 보인다
- 결정: 1. 내용은 아래와 같다.
  - **색**: 잉크 `#16233a`(단말기 몸체 남색 — 위 띠·주 버튼) + 강조색 하나 `#2f6bff`(LED 파랑 — 입력칸 초점·지금 탭·처리 버튼). 결과 색(합격·거절·경고)은 강조색과 따로 둔다. 시안에서 "현장만 초록"·"청록"을 나란히 보고 파랑으로 정했다(세 앱이 같은 색 → 같은 회사 화면으로 보인다). 0061의 "점주 앱(파랑)과 구분되게 초록"은 앱 표시 글자·탭 구성이 다르므로 색으로 구분할 필요가 없다고 보고 바꾼다
  - **글꼴**: IBM Plex Sans KR(본문) + IBM Plex Mono(시리얼·운송장·날짜). 한 가족이라 한글과 시리얼의 굵기·높이가 맞는다. Pretendard + JetBrains Mono도 시안에서 비교했다
  - **글꼴 넣는 법**: `@fontsource` 패키지를 `styles.css`에서 `@import`(main.tsx는 점주 앱 사본이라 건드리지 않는다 — 0062). 외부 CDN(Google Fonts)은 창고 PDA가 외부를 막은 망에 있으면 시스템 글꼴로 떨어진다. 한글 전체 파일(`korean-400.css`)은 굵기 하나에 woff2 517KB라 버리고, unicode-range로 나뉜 기본 CSS를 쓴다(브라우저가 화면에 나온 글자의 조각만 받는다). Sans 굵기는 400·700 둘만(600을 쓰는 자리는 브라우저가 700으로 그린다) — 셋이면 CSS가 gzip 101KB, 둘이면 70KB(실험 0018)
  - **움직임**: 상태가 바뀐 것을 알릴 때만. 새로 찍은 줄 배경 0.9초, 버튼 누름 `scale(.98)` 80ms. 스크롤 페이드인·겹침 레이아웃은 쓰지 않는다(업무 화면에서 정보를 늦게 보여 준다). `prefers-reduced-motion`이면 모두 끈다
  - **모양 규칙**: 오늘 요약 네 칸은 카드 넷이 아니라 한 판, 주 버튼(잉크)과 보조 버튼(흰 바탕 + 잉크 테두리)을 나눈다. 박스 목록의 거절된 줄은 줄째 왼쪽 빨간 띠 + 옅은 바탕(`li.rejected` — ScanPage가 줄 결과·줄 문제로 붙인다). 결과를 받은 박스는 주 버튼 모양이 "보내기"에서 "새 박스"로 옮겨 간다(초점이 이미 새 박스로 간다 — 0064). 처리 결과 요약(`.notice[role=status]`)은 경고가 아니라 알림 색
  - **넓은 화면**: 720px 이상이면 바탕을 잉크색으로 칠하고 가운데 한 줄을 둥근 기기 모양으로 띄운다(PC 전용 배치는 만들지 않는다 — 현장 일은 PDA, 사무실에서는 어드민 박스 스캔). 매장 앱은 다음 작업에서 900px 이상 두 단 배치를 더한다(시안에 있음)
  - 아이콘은 선 SVG 세 개(`components/icons.tsx`, `aria-hidden` — 링크 이름은 글자 그대로)
- 결과·대가: 처음 여는 화면의 전송량이 늘었다 — CSS 1.8KB → 69.5KB, 글꼴 woff2 0 → 204~223KB(14~15개 조각, 실험 0018). 두 번째부터는 캐시. `dist`는 328KB → 5.5MB(woff2·woff 조각 파일 수백 개, 내려받지 않는 조각 포함). 시스템 글꼴보다 첫 화면이 잠깐 시스템 글꼴로 그려졌다가 바뀐다(`font-display: swap`). CSS `:root`의 색 이름(`--accent` 등)은 남겨 두었다(다른 규칙이 쓴다) — `--accent`는 이제 잉크
- 다시 볼 조건: 창고 Wi-Fi에서 첫 화면이 느리다는 말이 나오면 쓰는 글자만 남기는 서브셋(빌드 때 화면 글자를 모아 woff2를 직접 만든다) 또는 시스템 글꼴로. 네 번째 화면 앱이 생기거나 세 앱이 같은 토큰을 세 번 고치게 되면 토큰만 공유 CSS 파일로 뺀다(0062의 workspaces 조건과 함께 본다)

### 보탬 (매장 앱, 2026-10-29)

- 같은 토큰·글꼴(`styles.css` `@import`, main.tsx는 그대로 — 현장 앱이 사본으로 본다). 위 띠는 흰 바탕 + 잉크 표시(점주 화면은 밝게), 주 버튼(접수하기·설치 확인)은 잉크, 링크·진행 단계는 파랑
- **오고 있는 단말기** 카드는 잉크 바탕(`.card.hero`) + 택배 단계 가로 막대(`StepBar`, 이름 표시). **진행 중 A/S** 카드는 이름 없는 막대. 막대는 `aria-hidden` — 글자 요약(운송장 한 줄, "지금 단계: …")이 따로 있다. 상세 화면의 세로 단계(`StepList`, `li.done` 등 클래스 그대로)는 칸을 선으로 이었다
- **연결 끊긴 사용 중 단말기**는 카드째 왼쪽 빨간 띠(`.card.offline`). 순서는 바꾸지 않았다(끊긴 것을 위로 올리는 것은 문구·정렬이 바뀌는 일이라 따로)
- **넓은 화면(900px 이상)**: 메뉴(`nav.tabs`)를 위 띠(`header`) 안으로 옮겼다 — 휴대폰에서는 `position: fixed`로 화면 아래에 그대로 붙고, 넓은 화면에서는 `position: static`이라 매장 이름 옆 메뉴가 된다. 메뉴를 두 벌 그리지 않아 링크 수·이름은 그대로다(DOM 순서는 메뉴가 본문 앞으로 — 키보드로는 메뉴를 먼저 지난다). 홈은 두 단(왼쪽: 오고 있는 단말기·진행 중 A/S, 오른쪽: 사용 중·회수 — DOM 순서가 휴대폰과 같아 감싸는 `div` 둘만 더했다), 다른 화면은 가운데 760px
- 시안의 PC 요약 세 칸·위 띠 "고장 접수" 버튼·문의 전화는 넣지 않았다(새 숫자·새 링크·실제 번호가 필요하다)
- 첫 화면 전송량은 현장 앱과 거의 같다(CSS 69KB, woff2 232KB — 실험 0018 추가)
