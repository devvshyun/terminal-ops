# 0071. 소개 페이지는 `apps/landing` 정적 페이지(Vite + GSAP)로, 숫자는 기록과 테스트로 묶는다

- 날짜 / 관련 기능: 2026-10-29 / 포트폴리오 소개(새 앱), 디자인(decisions/0070)
- 상황: 저장소를 처음 여는 사람(면접관)은 README보다 먼저 "무엇을 만들었나"를 한 화면에서 보고 싶어 한다. 업무 화면(0070)은 일부러 움직임을 줄였지만, 소개 페이지는 스크롤 연출·겹침 레이아웃·표현력 있는 타이포그래피를 쓰기로 했다(사용자 요청). 위험은 두 가지다 — 숫자를 부풀리거나 지어내는 것, 기록이 늘어도 페이지 숫자가 그대로인 것.
- 선택지:
  1. **`apps/landing` — Vite + 순수 TS + GSAP(ScrollTrigger·SplitText), api 없이 뜨는 정적 페이지** — 다른 앱과 같은 빌드 도구, 상대 경로 빌드(`base: './'`)로 GitHub Pages 같은 곳에 그대로 올린다. React가 필요 없다(상태가 없다)
  2. README를 길게 — 움직임·레이아웃을 못 쓴다
  3. 어드민 안의 소개 화면 — 로그인 뒤에 있고, 어드민 번들·테스트에 섞인다
  4. 바깥 사이트 빌더 — 저장소 밖이라 기록과 묶을 수 없다
- 결정: 1.
  - **타이포그래피**: 제목은 한글 가변 세리프 Hahmlet(`@fontsource-variable/hahmlet`, wght 100~900). 한 제목 안에 가는 획(300)과 굵은 획(800)을 섞는다("결제단말기 한 대의 / **일생을** / 기록합니다."). "일생을"은 열릴 때 200 → 800, "기록합니다."는 스크롤에 따라 300 → 700(가변 글꼴 축을 GSAP으로). 본문은 업무 화면과 같은 Plex Sans KR, 상태 코드·시리얼은 Plex Mono — 처음 화면 뒤에는 외곽선만 있는 큰 시리얼 `SN100-2610-00412`가 깔리고 열릴 때 숫자 칸이 돌다가 왼쪽부터 선다(공항 안내판). 생애주기 카드는 `RECEIVED`·`IN_SERVICE` 같은 코드를 그대로 머리글로 쓴다
  - **움직임**: 제목 줄 가림막 올리기(SplitText lines mask), 문단 아래에서 올라오며 나타나기(화면에 들어올 때 한 번), 생애주기 구간 고정 + 카드 줄 가로 이동(861px 이상, 휴대폰은 손가락으로 옆으로 미는 목록), 겹친 화면 사진의 서로 다른 속도(parallax), 숫자 세어 올라가기, 링크 밑줄이 왼쪽에서 자라기·기록 줄 hover 때 들여쓰기와 화살표. `prefers-reduced-motion`이면 스크립트 움직임을 하나도 걸지 않는다. 글은 모두 HTML에 있어 스크립트가 없어도 다 보인다(숫자·기록 목록만 스크립트가 채운다)
  - **숫자는 실험 기록에 적힌 값만**: `src/content.ts`의 숫자마다 출처 파일과 그 파일에 그대로 있어야 하는 글(`quote`)을 두고 `content.test.ts`가 파일을 열어 확인한다. 기록 제목은 파일 첫 줄과 같은지, 생애주기 상태 코드는 contracts 상태 값인지도 본다. 기록 수(결정·트러블슈팅·실험)는 빌드 때 `import.meta.glob`으로 파일 이름을 센다(손으로 적지 않는다)
  - 화면 사진은 현장·매장 앱을 가짜 api 응답으로 찍은 것(`public/shots/`) — 페이지에 "시연용 예시 데이터"라고 적는다. 어드민 사진은 어드민 디자인(0070 이후) 뒤에 더한다
  - 색은 0070 토큰(잉크·파랑)을 따르고, 잉크 구간과 종이 구간을 번갈아 둔다. 왼쪽 정렬, 처음 화면의 휴대폰 사진이 제목 오른쪽 끝을 덮는다(1100px 이상)
- 결과·대가: 빌드 `dist` 7.7MB(글꼴 조각 — Hahmlet 조각이 Plex보다 많다), 첫 화면이 받는 양은 재지 않았다. vitest는 다른 앱(5.0.4)과 달리 5.0.5(troubleshooting/0033). 화면 사진은 손으로 다시 찍어야 한다(앱 모양이 바뀌면 낡는다). GitHub 링크는 저장소가 공개일 때만 열린다
- 다시 볼 조건: 앱 모양이 크게 바뀌면 사진을 스크립트로 다시 찍는다(Playwright + 가짜 응답 — 이번에 쓴 방법을 `scripts/`로 옮긴다). 첫 화면이 무겁다는 말이 나오면 Hahmlet을 제목에 쓰는 글자만 남긴 서브셋으로

### 보탬 (패드·휴대폰 배치, 2026-10-29)

- 기준 폭을 셋으로: 휴대폰(599px 이하)·패드(600~1099px)·데스크톱(1100px 이상). 처음 화면의 제목·휴대폰 사진 두 단, 세 화면 사진 겹침(절대 위치 + parallax)은 데스크톱에서만. 처음에는 두 단이 861px부터 켜져 1024px(패드 가로)에서 제목이 사진 뒤로 들어갔고, 겹친 사진이 768~1024px에서 역할 글을 덮었다
- 패드·휴대폰: 처음 화면은 한 단(사진은 글 아래 가운데, 260·220px), 큰 제목은 화면 폭을 따라 `clamp(34px, 9.4vw, 100px)` + 줄마다 `nowrap`(낱말 중간 줄바꿈 없음). 세 화면은 흐름 배치(PC 사진 아래로 휴대폰 두 대가 음수 위 여백으로 올라와 겹친다 — 아래 글을 덮지 않는다), parallax 없음. 휴대폰에서는 뒤 시리얼을 위 문구가 아니라 사진 뒤쪽으로
- 생애주기 구간 고정·가로 이동은 그대로 861px 이상(패드 가로 포함), 그보다 좁으면 손가락으로 미는 목록
