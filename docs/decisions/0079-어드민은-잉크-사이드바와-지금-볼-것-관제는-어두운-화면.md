# 0079. 어드민은 잉크 사이드바와 "지금 볼 것", 관제는 어두운 화면으로(같은 토큰)

- 날짜 / 관련 기능: 2026-10-29 / 어드민(`apps/admin`), 운영 관제(`apps/console`, 보강 6), 디자인 2
- 상황: 현장·매장 앱은 디자인 토큰(decisions/0077)을 적용했지만 어드민과 관제는 GitHub 기본 색에 시스템 글꼴 그대로다. 어드민 처음 화면은 카드 일곱 장이 같은 무게라 무엇부터 볼지 안 보이고, 상태 열두 줄 목록이 길다. 관제 대시보드는 0과 실패 수가 같은 무게라 문제 있는 큐가 묻힌다. 시안 v2(아티팩트 "단말온 업무 화면 시안")로 지금 화면과 나란히 놓고 사용자가 고른 것(관제는 어둡게, "지금 볼 것" 세 칸, 상태 칩은 전체 기준 수임을 적기)을 따른다.
- 선택지:
  1. **같은 토큰·글꼴(0077)에 앱마다 배치만 다르게** — 어드민은 잉크 사이드바 + 밝은 본문, 관제는 어두운 화면. 새 API 없이 이미 받는 값으로 "지금 볼 것"·생애주기 막대·주의 줄을 만든다
  2. 어드민·관제를 하나의 앱으로 합친다 — 보강 6이 별도 앱으로 정한 이유(decisions/0074)가 그대로다
  3. 차트 라이브러리를 들인다 — 막대 몇 개라 CSS `flex-grow`로 충분하다. 번들·의존이 는다
- 결정: 1.
  - **어드민 틀**: 위 띠를 없애고 왼쪽 잉크 사이드바(232px)에 앱 표시, 묶음 메뉴(업무 · 점검·리포트 · 관리 — `nav.ts`의 `group`), 다른 화면(준비 중인 화면은 설명 줄을 숨김), 맨 아래 로그인한 사람(사이드바가 길어도 `position: sticky`로 보임). 메뉴 링크 수·이름은 그대로(역할별 메뉴 테스트)
  - **어드민 처음 화면**: 맨 위 "지금 볼 것" 세 칸 — 오래 오프라인·배송 뒤 설치 안 됨(`anomalies.byRule`, 이름은 서버의 규칙 label)과 VAN 어긋남(`van.confirmed`). 0이면 초록 테두리. 단말기 카드는 한 줄 전체에 생애주기 막대(상태를 여섯 구간으로 — `lib/labels.ts` `STATUS_STAGE`, 현장·매장 앱과 같은 구간), 접속 상태는 비율 막대. 막대는 `aria-hidden`(같은 수가 글자로 있다). 기존 카드·글자는 그대로
  - **단말기 목록**: 상태는 구간 색 이름표(`StatusBadge`), 시리얼은 고정폭, 가맹점은 이름 + 코드(이미 받는 `/merchants`), 줄 어디를 눌러도 상세(시리얼 링크를 줄 전체로 넓힘 — `tr { position: relative }` + `a::after { inset: 0 }`). **상태 칩**은 처음 화면 집계(`/dashboard/summary`, 30초 캐시)의 상태별 수를 칩으로 보이고 누르면 그 상태로 1쪽부터 거른다 — 수가 **전체 기준**(검색 조건과 상관없다)이라는 글을 칩 옆에 둔다. 집계를 부를 수 있는 사무실 역할만. 칩은 구간이 아니라 상태 하나씩이다(서버 거르기가 상태 하나만 받는다)
  - **관제**: 어두운 화면이 기본(오래 띄워 두는 화면 — 밝은 화면으로 바꾸는 단추는 두지 않는다). 대시보드 맨 위 "주의"(워커 0·남은 실패·없으면 최근 실패·멈춤·응답 없는 MySQL·Redis)를 이미 받은 값에서 고르고, 같은 기준으로 큐 줄 왼쪽에 빨간 띠(`tr.troubled`). 0인 칸은 흐리게(`td.zero`), 최근 완료 수 옆 처리량 막대. "주의"는 `role="alert"`·`status`를 쓰지 않는다 — 오류 칸 수와 "마지막 갱신" 상태 하나를 보는 기존 테스트·화면 읽기 도구와 섞이지 않게 이름 붙은 영역(`aria-label="주의"`)으로
  - 글꼴은 0077과 같은 `@fontsource` 넷(Sans 400·700, Mono 400·600)을 `styles.css`에서 `@import`
- 결과·대가: 단말기 목록이 처음 화면 집계를 한 번 더 부른다(캐시 30초, 사무실 역할만). 기존 테스트 하나(`roles.test.tsx` — 세션 끝남을 `/dashboard/summary` 401로 만들던 것)가 목록의 새 호출과 겹쳐 401을 `/health`로 옮겼다(시험하는 것 — 401 뒤 캐시 비움 — 은 같다). 메뉴의 할 일 수(A/S 17, 이상 23)는 넣지 않았다 — 틀(Layout)이 화면마다 집계를 부르게 되고, 그 요청을 모르는 다른 화면 테스트가 404 오류를 본다. 관제 메뉴의 "실패 job" 수도 같은 이유로 넣지 않았다
- 다시 볼 조건: 단말기 목록의 칩을 지금 검색 조건 기준 수로 바꿔야 하면 `/terminals`에 상태별 수(facet)를 더한다(api 작업 — 계약·접근 표). 메뉴에 할 일 수를 넣으려면 가벼운 `/dashboard/counts` 같은 응답과 테스트 공용 가짜 응답을 함께
