# 0080. 개발자센터는 ADMIN이 쓰는 별도 앱 apps/developers로

- 날짜 / 관련 기능: 2026-10-29 / 보강 7, 외부 연동(decisions/0054·0069)
- 상황: 외부 업체 키 API와 외부용 읽기 API가 있지만 화면이 없다. 0069가 "키 발급·폐기는 연동 문서·호출 로그와 함께 개발자센터에서"로 정했다. 누가 이 화면을 쓰느냐가 범위를 가른다.
- 선택지:
  1. **ADMIN이 업체를 대신해 관리하는 화면(사내용)** — 업체 등록·키 발급·폐기·호출 로그·문서를 ADMIN 로그인으로. 새 역할이 없다
  2. 업체가 직접 로그인하는 셀프서비스 — 업체 계정(새 역할 PARTNER)·업체별 데이터 경계(자기 키·자기 호출만)·비밀번호 재설정·초대가 필요하다. 사람 세션과 외부 키가 섞이는 지점이 늘어 0054의 "사람 세션으로는 `/partner/v1`을, 키로는 사내 API를 부를 수 없다" 경계를 다시 따져야 한다
  3. 어드민 안에 메뉴로 — 앱이 늘지 않지만, 0069가 버린 "두 벌" 문제(어드민 메뉴가 외부 연동 화면으로 커진다)와 연동 문서가 사내 화면 안에 들어가는 모양이 된다
- 결정: 1. `apps/developers`(:5178·미리보기 4178), 관제 앱(0074·0075)과 같은 방식 — 점주 앱 사본 + 사본 검사(0062), Vite 프록시로 같은 출처, 디자인 토큰(0077). 로그인한 사람이 ADMIN이 아니면 화면을 열지 않고 안내만 한다(API도 ADMIN만 — 화면은 보기 좋게 막을 뿐, 막는 곳은 서버다).
- 결과·대가: 업체는 자기 호출 로그를 직접 보지 못한다 — ADMIN이 보고 알려 준다(0054가 "업체가 자기 호출을 보는 곳"이라 적은 것과 다르다). 연동 문서(OpenAPI JSON)만 로그인 없이 열려 있다(decisions/0083). 로컬에서는 :5173~5178 앱이 sid 쿠키 하나를 함께 쓴다(0074 그대로, 보강 9에서 호스트 이름을 나누면 풀린다).
- 다시 볼 조건: 실제 외부 업체가 붙어 자기 키를 돌려 쓰거나 호출을 직접 봐야 할 때(2로, PARTNER 역할과 업체 경계 설계부터).
