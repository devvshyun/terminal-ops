# 0084. 가상 업체 콘솔과 시뮬레이터 화면은 한 앱 apps/sandbox로, 로그인 없이

- 날짜 / 관련 기능: 2026-10-29 / 보강 8, 가상 업체 서버(`apps/partners`)·단말기 시뮬레이터(`apps/device-sim`)
- 상황: 두 서버는 시연·테스트용으로 관리 API(`/__admin/*`)만 있고 화면이 없다. 어드민 "다른 화면"에 "가상 업체 콘솔"·"단말기 시뮬레이터" 두 자리가 "준비 중"이다(decisions/0067). 두 서버는 인증이 없고 `127.0.0.1`에만 열린다.
- 선택지(앱):
  1. **한 앱 `apps/sandbox`(:5179)에 메뉴 둘(가상 업체·단말기 시뮬레이터)** — 같은 사람(시연하는 개발자)이 같은 시연에서 번갈아 쓴다. 어드민의 두 자리는 같은 앱의 두 경로를 가리킨다
  2. 앱 둘 — 포트·설치·빌드가 하나씩 더 는다. 나눌 이유(다른 사람, 다른 권한)가 없다
  3. 관제 앱(`apps/console`) 안 메뉴로 — 관제는 운영 시스템을 보는 화면이고 가짜 업체·가짜 단말기를 조작하는 일은 시연 무대 뒤의 일이다. 섞으면 "운영 화면에서 장애를 켠다"처럼 보인다
- 선택지(로그인):
  1. **없음** — 두 서버 자체가 인증이 없다. 화면에 로그인을 붙여도 서버는 누구나 부를 수 있어 막는 것이 없다
  2. 사내 로그인(api 세션) — api와 상관없는 두 서버 앞에 세션 검사를 둘 곳이 없다(Vite 프록시 뿐). 보안처럼 보이기만 한다
- 결정: 앱 1, 로그인 1. Vite 개발 서버가 `/partners` → :4010, `/sim` → :4020으로 넘긴다(같은 출처, 두 서버에 CORS를 열지 않는다). 화면 첫머리에 "시연용 가짜 서버를 조작하는 도구"라고 적는다. 공용 코드 사본(0062)은 쓰지 않는다 — 세션·api 클라이언트가 필요 없다. 디자인 토큰은 0077 그대로.
- 결과·대가: 시연 도구 주소를 아는 누구나 장애를 켤 수 있다(로컬 시연 전제). 보강 9에서 Docker로 묶을 때 partners·device-sim·sandbox 포트를 바깥에 열지 않거나 묶음 안에서만 쓴다 — 그때 결정 기록. 화면 앱이 일곱이 된다.
- 다시 볼 조건: 시연 환경을 남이 접속하는 곳(공유 서버)에 올릴 때(두 서버 앞에 인증이나 네트워크 제한).
