# 0085. 가상 업체 서버에 최근 요청 기록, 시뮬레이터에 단말기 목록

- 날짜 / 관련 기능: 2026-10-29 / 보강 8(decisions/0084)
- 상황: 시연 도구가 "업체가 무엇을 받았나"와 "어느 단말기가 꺼져 있나"를 보여 줘야 한다. 가상 업체 서버에는 수만 센 `GET /__admin/stats`와 톡톡 메시지 목록이 있고, 지금 설정을 읽는 API가 없다(설정은 `POST /__admin/config`의 응답으로만 보인다). 시뮬레이터에는 단말기 한 대 조회(`/__admin/devices/:serialNo`)만 있다.
- 선택지(업체 요청):
  1. **메모리 고리 200개 + `GET /__admin/requests?limit=`** — 응답이 끝날 때(`finish`) 한 줄. 업체(경로 첫 마디)·메서드·쿼리 포함 경로·상태·걸린 시간. 관리 API는 넣지 않는다(시연 도구가 5초마다 읽는 요청이 기록을 채우지 않게). `reset`이 비운다
  2. 요청·응답 본문까지 — 톡톡 파일 첨부(base64) 등으로 메모리가 커지고, 화면에 다 보일 이유가 없다(톡톡 메시지는 따로 있다)
  3. 파일 로그 — 서버가 테스트마다 뜨고 내려가 파일이 쌓인다
- 선택지(단말기 목록): 전부 / **수 넷(전체·온라인·오프라인·업데이트 중) + 시리얼 순 앞 limit대(기본 100, 최대 1000)** — 시뮬레이터는 2만 대까지 돈다. 화면 표는 앞부분만 보이고 수는 전체를 센다.
- 결정: 업체 1, 단말기 2. 그리고 `GET /__admin/config`(지금 설정 그대로)를 더한다 — 화면이 손잡이의 지금 값을 서버에서 읽게.
- 결과·대가: 요청 기록은 재시작하면 사라진다. 200개를 넘으면 오래된 것부터 버린다(`total`은 받은 수 전부). `reset` 직전에 받아 `reset` 뒤에 끝난 요청은 새 기록에 들어간다(시연 도구용이라 받아들인다). 업체 설정 값 검증은 여전히 없다(화면이 범위를 막는다 — 0084).
- 다시 볼 조건: 시연에서 요청 본문(예: 운송장 발급 내용)을 보여 줘야 할 때.

### 보탬 (최종 검토 반영, 2026-10-29)
- 'finish'만 들으면 지연 손잡이를 켰을 때 보낸 쪽이 먼저 끊은 요청(실험 0014의 장면)이 빠졌다 → 'close'에서 기록하고 다 보내지 못했으면 상태 0. `GET /__admin/requests?partner=`로 서버에서 거른 뒤 자른다
- 처음 버전은 'finish' 리스너 안에서 `new URL(req.url)`을 불러, `GET http://[bad HTTP/1.1` 같은 깨진 주소에 리스너가 던져 서버 프로세스가 죽었다(테스트에서 `TypeError: Invalid URL`로 재현). 업체 이름은 경로 문자열의 첫 마디로만 뽑는다
