# 0088. 시연 화면은 호스트 이름별로 — 앱마다 쿠키가 따로

- 날짜 / 관련 기능: 2026-10-29 / 보강 9, decisions/0057·0061·0074(쿠키 공유)
- 상황: 개발 서버에서는 화면 앱이 `localhost`의 포트만 다르다. 쿠키는 포트를 가리지 않아 `sid` 하나를 모두 함께 쓴다 — 한 화면에서 점주로 로그인하면 어드민도 점주가 되고, 한 곳에서 로그아웃하면 모두 로그아웃된다(0074). 시연은 "운영자 화면과 점주 화면을 나란히" 보여 줘야 한다.
- 선택지:
  1. **호스트 이름별(`admin.localhost:8080`, `merchant.localhost:8080` …)** — api 쿠키는 Domain을 주지 않아(host-only) 앱마다 따로다. 브라우저가 `*.localhost`를 이 PC로 푼다(RFC 6761 — Chrome·Edge·Firefox). 앱은 모두 같은 출처의 `/api`를 부르고 nginx가 api로 넘긴다(CORS 없음 그대로)
  2. 경로별(`/admin/`, `/merchant/`) — 출처가 하나라 쿠키가 여전히 하나다. 앱마다 Vite base·라우터 basename도 바꿔야 한다
  3. 포트별(지금처럼) — 0074 그대로
- 결정: 1. `localhost:8080`(소개 페이지), `admin`·`merchant`·`field`·`console`·`developers`·`sandbox`.localhost:8080. 화면끼리 건너가는 링크(어드민 "다른 화면", 현장 → 어드민)는 빌드 때 `VITE_*_URL`로 이 주소들을 넣는다(0067의 env 그대로). 쿠키 `SameSite=Strict`도 그대로 — 다른 하위 도메인에서 넘어온 첫 이동에는 쿠키가 붙지 않지만, 앱마다 따로 로그인하므로 문제가 없다.
- 확인: 리허설에서 같은 브라우저 컨텍스트로 어드민(운영자)과 매장(점주)을 함께 로그인 → `sid` 쿠키가 `admin.localhost`·`merchant.localhost` 둘, 어드민을 새로고침해도 운영자 그대로(devlog 2026-10-29 보강 9 리허설).
- 결과·대가: `*.localhost`를 풀지 않는 브라우저(일부 Safari)는 `/etc/hosts`에 이름을 더해야 한다(시나리오 문서). Node·curl은 `*.localhost`를 풀지 않는다 — 스크립트는 `127.0.0.1`에 `Host` 헤더로 부른다. 개발 서버(포트별)의 쿠키 공유는 그대로다(0074) — 시연은 시연 묶음으로.
- 다시 볼 조건: 실제 도메인에 올릴 때(하위 도메인 쿠키 범위·HTTPS).
