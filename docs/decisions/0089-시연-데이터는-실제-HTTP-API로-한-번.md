# 0089. 시연 데이터는 실제 HTTP API로, 한 번만

- 날짜 / 관련 기능: 2026-10-29 / 보강 9
- 상황: 띄우자마자 시연할 수 있으려면 운영 중 단말기·배송 중·A/S·발주·VAN 어긋남·주간 리포트가 있어야 한다. 시뮬레이터는 api에 운영 중으로 있는 시리얼로 하트비트를 보내야 받아들여진다(보강 8에서 모두 "거절"이던 이유).
- 선택지:
  1. **실제 HTTP API로 만드는 스크립트**(`apps/api/src/db/scenario.ts`, 시연 계정으로 로그인) — 전이 서비스·이력·Outbox·택배 운송장(가상 업체)·VAN 대조를 운영과 같은 길로 지난다. 화면의 이력·톡톡 알림이 진짜로 쌓인다. CLAUDE.md "상태 변경은 전이 서비스 한 곳으로만"을 지킨다
  2. SQL·엔티티로 직접 넣기 — 빠르지만 이력·Outbox·Redis 사본(접속·운영 중 목록)을 손으로 맞춰야 하고, 전이 규칙을 우회한다
  3. DB 덤프를 시드로 — 빠르지만 마이그레이션이 바뀌면 덤프가 깨지고, 무엇이 들어 있는지 코드로 읽을 수 없다
- 결정: 1.
  - 이미 했으면 건너뛴다: 마지막에 만드는 외부 업체 `HANOL-POS`가 있으면 끝. 첫 단말기(`DM-0001`)는 있는데 그 업체가 없으면(도중에 멈춤) 멈추고 `down -v`를 안내한다 — 반쯤 들어간 데이터에 덧붙이지 않는다
  - 가상 업체(세움 덜 보내기 → 발주 → 되돌리기, 브릿지VAN 등록)와 시뮬레이터(시리얼·주기·시작, 회수 대기 단말기는 꺼 둠)는 관리 API로
  - 키 원문을 출력하지 않는다(테스트가 본다). 운영(`NODE_ENV=production`·`SEED_DEMO=0`)이면 돌지 않는다(시연 계정이 없다, 0054)
  - e2e `seed-scenario.e2e.spec.ts`: 테스트 앱을 포트로 띄워 스크립트가 진짜 HTTP로 끝까지 돌고, 두 번째는 건너뛴다(건너뛰기를 빼면 실패하는 것도 확인)
- 결과·대가: 시각을 고치지 않아 "며칠 지나야 걸리는" 이상 단말기 규칙(오래 오프라인·배송 뒤 설치 안 됨 등)은 띄운 직후 0건이다. 시연 데이터는 시연 계정 비밀번호로 로그인한다 — 시연 중 그 비밀번호를 바꾸면 다음 `down -v` 전까지는 문제가 없지만 새로 넣을 때 실패한다. 띄우는 데 약 30초(이 컨테이너, 이미지가 이미 있을 때 `up`부터 demo-seed 끝까지 32초 — devlog).
- 다시 볼 조건: 시연에 이상 단말기가 꼭 있어야 할 때(테스트용 시각 주입 — 운영 코드에 시계 의존성 넣기), 데이터가 수천 건이 필요할 때(일괄 API).
- 뒤 기록: 2026-10-30 [0091](0091-시연-데이터의-지난-일은-두-대만-시각을-옮긴다.md)이 "시각을 고치지 않는다"를 단말기 두 대(DM-0021·0022)에 한해 뒤집었다 — 띄운 직후 이상 단말기 카드가 0이 아니게.
