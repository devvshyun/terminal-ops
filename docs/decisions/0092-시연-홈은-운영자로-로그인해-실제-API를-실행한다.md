# 0092. 시연 홈은 운영자로 로그인해 실제 API를 실행한다

- 날짜 / 관련 기능: 2026-10-30 / 보강 10 시연 홈(`apps/demo-home`)
- 상황: 시연 홈은 단계마다 "실행 단추 + 바로 옆 결과"를 둔다(Stripe Shell식). 배정·출고·펌웨어 배포·A/S 교체 같은 실행과 대시보드·택배 수집 이력·배포 단계 같은 결과는 모두 로그인한 운영자 권한(OPERATOR·OFFICE)이 필요하다. 장애 손잡이(가상 업체·시뮬레이터)는 로그인이 없다(0084).
- 선택지:
  1. **시연 홈에서 운영자(`operator`)로 한 번 로그인** — 시연 홈 호스트(`demo.localhost`)의 쿠키라 다른 화면 로그인과 섞이지 않는다(0088). 실행·결과 모두 운영 API 그대로 — 권한 검사·전이 서비스·이력을 그대로 지난다
  2. api에 시연 전용 엔드포인트·역할(예: `/demo/run-act-3`) — 시연 홈이 짧아지지만 운영 API 옆에 시연용 뒷문이 생기고, 시연이 보여 주려는 "실제로 이렇게 돈다"가 흐려진다
  3. 실행 없이 안내만(어느 화면에서 무엇을 누르라) — 지금 시나리오 문서와 같다. 결과를 바로 옆에서 못 본다
  4. 시연 계정 비밀번호를 화면 코드에 넣어 자동 로그인 — 공개 저장소의 시연 값이긴 하지만, 화면 묶음에 비밀번호를 굳히는 길을 만들지 않는다
- 결정: 1. 로그인 폼에 아이디 `operator`를 미리 채우고 비밀번호는 사람이 넣는다(값은 `seed-accounts.ts` — 0054). 운영자가 아니면 결과는 보이되 실행 단추는 안내로 바뀐다(관제·ADMIN 화면이 필요한 단계는 "화면 열기"로). 막·단계 진행 표시는 이 브라우저의 localStorage만(서버에 남기지 않는다 — 지워져도 시연은 된다).
- 결과·대가: 시연 홈에서 한 실행도 이력의 사람은 `operator`다(시연 홈인지 어드민인지 구분하지 않는다). 운영 관제(MONITOR)의 큐·실패 job은 시연 홈에서 읽지 못해 "화면 열기"로 넘긴다. 시연 홈은 로그인 없는 두 서버(가상 업체·시뮬레이터)도 부른다 — 묶음 밖으로 열지 않는다(0087 그대로).
- 다시 볼 조건: 시연 홈을 남이 접속하는 곳에 올릴 때(시연 홈 자체 접근 제어), 관제 결과를 시연 홈에서 꼭 보여야 할 때(시연 홈에 관제 로그인 하나 더).
