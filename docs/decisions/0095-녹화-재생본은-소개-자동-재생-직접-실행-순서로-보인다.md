# 0095. 녹화 재생본은 소개 → 자동 재생 → 직접 실행 순서로 보인다

- 날짜 / 관련 기능: 2026-10-30 / 보강 11 후속(녹화 재생본, decisions/0093)
- 상황: 첫 배포본을 본 사용자가 "이 페이지의 의미를 모르겠다", "녹화본을 녹화해서 시연 영상을 순서대로 보여 준다는 것 아니었나"라고 했다. 사용자가 기대한 것은 **열면 순서대로 재생되는 시연**이었다. 배포본은 아무 설명 없이 1막을 띄우고 보는 사람이 [실행]을 하나씩 눌러야 했다. "녹화"를 사용자는 영상으로, 나는 응답 데이터로 이해했다 — 0093 선택지 표에서 이 차이를 짚지 않았다. 사용자는 순서를 정해 주었다: 1) 소개 페이지 2) 녹화 재생본으로 소개(자동 진행) 3) 그 뒤 단편적으로 직접 실행. 그리고 사진을 하나하나 눌러야 보이는 것이 불편하다고 했다
- 선택지:
  1. **화면이 스스로 진행하는 자동 재생** — 자동 재생기가 화면의 실행 단추를 찾아 누르고, 단계마다 자막을 띄우고, 기다리는 장면은 녹화 시계가 흐르기를 기다린다. 장점: 보는 방식은 영상과 같고, 화면은 진짜(글자 선명·복사 가능), 멈추면 그 자리에서 직접 눌러 볼 수 있다, 녹화본만 다시 찍으면 된다. 단점: 단추를 찾는 등록부가 하나 더 생긴다
  2. 실제 영상 파일(Playwright 화면 녹화 → mp4) — 장점: README·이력서에 붙이기 쉽다. 단점: 화면을 바꾸면 영상도 다시 찍어야 한다, 글자가 흐리다, 영상과 직접 실행이 따로 논다
  3. 둘 다 — 대가가 합쳐진다
- 결정: 1. 자동 재생기는 사람이 누르는 것과 같은 함수(실행 단추의 useMutation)를 부른다 — 진행 표시·결과 패널 다시 읽기·녹화 시계 옮기기가 사람이 눌렀을 때와 똑같다. 사진은 단계 카드 안에 바로 보인다(누르면 크게). 왼쪽 "다른 화면"만 링크로 둔다
- 구조:
  - 첫 화면 `src/replay/Intro.tsx` — 프로젝트 소개, 볼 수 있는 백엔드 동작 6개, [시연 보기]·[바로 직접 눌러 보기]
  - 순서와 자막 `src/replay/tour.ts`(22단계, 막 순서)
  - 실행 단추 등록부 `src/replay/runners.ts`(Run이 단계 key·글자로 등록)
  - 아래 막대·진행 고리 `src/replay/TourBar.tsx`(일시정지·계속·다음·직접 해 보기)
- 결과·대가: 자동 재생 한 바퀴 약 2분 35초(브라우저 리허설). 자막은 업무 용어를 모르는 사람 기준으로 따로 썼다 — 단계 카드의 설명(운영자용)과 두 벌이다. 보통 시연 홈(시연 묶음)은 바뀌지 않는다(소개·자동 재생은 재생본에서만)
- 다시 볼 조건: 링크 대신 영상이 필요한 자리(이력서 첨부 등)가 생기면 2를 더한다 — 자동 재생을 Playwright로 녹화하면 된다
