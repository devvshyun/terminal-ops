# 0096. GitHub Pages는 소개 페이지 → 시연 영상 / 시연하기 세 갈래로

- 날짜 / 관련 기능: 2026-10-30 / 보강 11 후속(0093·0095를 바로잡음)
- 상황: 0095 배포본을 본 사용자가 소개 앱(`apps/landing`) 화면을 보이며 다시 설명했다 — "데모 페이지에 들어가면 이 소개 페이지가 나오고, 시연 영상 보기에 들어가면 시연 영상이 나오고, 시연하기 단추를 누르면 시나리오대로 시연할 수 있어야 한다. 어렵게 설명한 것도 아닌데." 0095는 시연 홈 안에 새 소개 화면을 만들고 "자동 진행"을 영상 대신으로 내놓았다. 사용자가 말한 소개 페이지는 이미 있는 소개 앱이었고, 시연 영상은 진짜 영상 파일이었다. 두 번 연속 요청을 내 식으로 바꿔 읽었다
- 선택지:
  1. **세 갈래** — 사이트 뿌리 = 소개 앱, `video.html` = 영상 파일(mp4), `demo/` = 시연 홈 녹화 재생본. 장점: 사용자가 말한 그대로. 소개 앱은 원래 정적이라 그대로 올라간다. 단점: Pages 작업이 두 앱을 빌드해 묶어야 한다, 영상 파일(약 3MB)이 저장소에 들어간다
  2. 0095 유지(시연 홈 안 소개 + 자동 진행) — 사용자가 거절한 구조
- 결정: 1 — 영상 부분은 decisions/0097에서 "실제 앱을 조작한 녹화"로 바꿨다
  - 영상은 시연 홈의 자동 진행(0095)을 Playwright로 화면 녹화해 H.264 mp4로 만든다(`apps/demo-home/scripts/record-video.cjs`). 자동 진행은 영상의 원본이자 시연 홈 위 막대의 "▶ 자동 진행" 단추로 남는다
  - 시연 홈 안의 소개 화면은 지웠다 — 시연하기는 바로 1막
- 주소:
  - 소개 앱의 두 단추(첫 화면과 위 메뉴)는 빌드 때 `VITE_DEMO_URL`·`VITE_VIDEO_URL`로 정한다
  - GitHub Pages: `./demo/`, `./video.html`
  - 시연 묶음(web 이미지): `http://demo.localhost:8080` — 실제로 도는 시연 홈
- 결과·대가:
  - 저장소에 mp4(약 2.8MB)와 첫 장면 사진이 들어간다
  - 녹화본을 다시 찍으면 영상도 다시 만들어야 한다(명령 하나, 약 3분)
  - 영상 첫 장면의 "온라인 0"은 녹화 직후 시뮬레이터가 아직 보고하기 전의 실제 값이다
- 배운 것: 사용자가 화면을 가리키며 말하면 그 화면이 기준이다. 비슷한 것을 새로 만들지 않는다. 구조 요청은 "주소 → 무엇이 보이는가" 표로 먼저 되묻는다
