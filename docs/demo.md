# 시연 시나리오 — 단말온 운영 시스템 한 바퀴

결제단말기 운영사 "단말온"(가상)의 단말기 한 대가 공장에서 나와 가맹점에서 쓰이다 고장 나 바뀌는 길을, 사람마다 다른 화면으로 따라간다. 등장하는 회사·가맹점은 모두 가상이다.

## 0. 띄우기

```bash
cp .env.example .env        # DEVICE_API_KEY만 임의의 값으로(README "실행")
docker compose -f docker-compose.demo.yml up -d --build
docker compose -f docker-compose.demo.yml ps   # migrate·demo-seed는 Exited (0), 나머지는 Up
```

- 처음 빌드는 몇 분 걸린다. 다 뜨면 `demo-seed`가 시연 데이터를 넣고 끝난다(`docker compose -f docker-compose.demo.yml logs demo-seed`에 "시연 데이터 완료").
- 계정은 역할마다 하나다: `admin`·`operator`·`monitor`·`field`·`merchant-gangnam`·`merchant-yeoksam`·`merchant-pangyo`. 비밀번호는 `apps/api/src/db/seed-accounts.ts`(로컬 시연 전용 값)에 있다.
- 화면마다 주소가 다르고, 로그인도 화면마다 따로다. 한 브라우저에서 어드민은 운영자로, 매장은 점주로 동시에 열어 둘 수 있다.
- 처음부터 다시: `docker compose -f docker-compose.demo.yml down -v`
- 볼륨을 두고 `down` → `up`하면 시연 데이터(MySQL)는 그대로이고, demo-seed가 건너뛰면서 메모리에만 있는 상태(브릿지VAN 등록, 시뮬레이터 설정·시작)를 다시 맞춘다. 세움전자 발주의 납품 명세는 업체 서버 메모리에만 있어 사라진다 — 그때는 어드민에서 새로 발주해 5번을 한다

| 주소 | 화면 | 누가 |
|---|---|---|
| http://localhost:8080 | 소개 페이지 | 누구나 |
| http://admin.localhost:8080 | 운영 어드민 | 운영자·관제·ADMIN |
| http://merchant.localhost:8080 | 매장(휴대폰) | 가맹점주 |
| http://field.localhost:8080 | 현장(휴대폰·PDA) | 현장 작업자 |
| http://console.localhost:8080 | 운영 관제 | 관제 |
| http://developers.localhost:8080 | 개발자센터 | ADMIN |
| http://sandbox.localhost:8080 | 시연 도구(가상 업체·시뮬레이터) | 시연자 |

`*.localhost`는 Chrome·Edge·Firefox가 이 PC로 푼다. 풀리지 않는 브라우저(일부 Safari)는 `/etc/hosts`에 `127.0.0.1 admin.localhost merchant.localhost field.localhost console.localhost developers.localhost sandbox.localhost`를 더한다.

## 2. 순서

| # | 누가 · 화면 | 할 일 | 보이는 것 |
|---|---|---|---|
| 1 | 운영자 · 어드민 처음 화면 | `operator`로 로그인 | "지금 볼 것"에 VAN 어긋남 4건, 생애주기 막대, 접속 막대(운영 중 11대). 띄운 직후 1분쯤은 접속이 "기록 없음"이다(1분마다 접속 스냅샷) |
| 2 | 운영자 · 어드민 "단말기" | 상태 칩 "배송 중" 또는 "배송 완료"를 고르고 `DM-0019`를 연다 | 운송장과 택배 이력. 1~2분 안에 워커가 배송 완료로 바꾼다(배치 실행 이력에 수집 결과) |
| 3 | 가맹점주 · 매장 | 다른 탭에서 `merchant-yeoksam`로 로그인 | 오고 있는 단말기(교체품 DM-0013 포함)와 택배 단계, A/S #2 "교체 진행 중". 어드민 탭은 새로고침해도 운영자다(쿠키가 `admin.localhost`·`merchant.localhost`로 따로) |
| 4 | 시연자 · 시연 도구 "가상 업체" | 번개택배 "429 확률" 50% → 적용 | 최근 요청에 429가 섞이고, 어드민 "배치 실행 이력"에 다시 시도가 보인다. 끝나면 "모두 기본값으로"가 아니라 0으로 되돌린다(기본값으로는 받은 데이터도 지운다) |
| 5 | 현장 작업자 · 현장 "박스 스캔" | 먼저 시연 도구 "세움전자 납품 명세"에 발주번호(어드민 "발주 입고 대조")를 넣고 시리얼을 복사한다. `field`로 로그인 → "발주분 입고" → 발주 고르기 → 시리얼 칸에 붙여 넣기(또는 한 줄씩 Enter) → 보내기 | 8줄 모두 "입고됨". 명세 밖 시리얼을 섞으면 그 줄은 빨간 띠 |
| 6 | 운영자 · 어드민 "발주 입고 대조" | 발주번호 단추 → 대조 패널 → 마감(확인창) | 발주 10 · 명세 8(차이 2) · 입고 8, 마감 뒤 CLOSED |
| 7 | 운영자 · 어드민 단말기 상세 | 재고 `DM-0014` → 가맹점 배정 → 출고 | 운송장 번호, 매장 홈에 오고 있는 단말기 |
| 8 | 가맹점주 · 매장 "고장 접수" | `merchant-gangnam`으로 `DM-0003` 접수 | 어드민 A/S에 새 접수 |
| 9 | 운영자 · 어드민 "펌웨어 배포" | 새 배포 만들기 → SN-100 · 1.1.0(단계 10·50·100%, 기본값) → 배포 시작(확인창) | 30초 안에 세 단계를 마치고 "완료"가 된다(11대 모두 성공 보고). 시연 도구 단말기 표의 펌웨어가 1.1.0으로 바뀐다 |
| 10 | 시연자 · 시연 도구 "단말기 시뮬레이터" → 어드민 | 펌웨어 실패율 60% → 설정 적용 → 어드민에서 1.2.0 등록 → 새 배포 | 10초쯤 뒤 "자동 중단: 1단계 실패율 50% (1/2) > 기준 20%". 끝나면 실패율을 0으로 되돌린다 |
| 11 | 시연자 · 시연 도구 | 단말기 `DM-0005` 끄기 | 90초쯤 뒤(HEARTBEAT_OFFLINE_AFTER_MS) 어드민 단말기 상세의 접속 상태가 오프라인이 되고, 톡톡 메시지에 오프라인 알림 |
| 12 | 관제 · 운영 관제 | `monitor` 로그인 | 큐·워커·최근 15분 처리량. 실패 job이 있으면 다시 시도 |
| 13 | ADMIN · 개발자센터 | `admin` 로그인 → 한올POS(가상) → 키 발급 | 원문은 한 번만. "연동 문서"의 curl을 http://localhost:8080 밖(api는 묶음 안)에서 부르려면 아래 "외부 API" |
| 14 | 운영자 · 어드민 "주간 리포트" | 지난주 보내기(이미 보냄) | 시연 도구 톡톡 메시지에 첨부 |

### 외부 API(개발자센터 키로)
api는 바깥에 열리지 않는다(decisions/0087). 시연에서 외부 업체 호출을 보이려면 웹 주소로 부른다 — 개발자센터 호스트의 `/api`가 api로 넘어간다:

```bash
curl -H 'Authorization: Bearer <키>' http://developers.localhost:8080/api/partner/v1/merchants/GANGNAM-KIMBAP/terminals
```

## 3. 알아 둘 것
- 이미 그 버전인 단말기에 같은 버전을 다시 배포하면, 단말기가 보고하지 않아 단계 시간 제한(기본 30분)이 지나야 "관측으로 성공" 처리된다(troubleshooting/0021). 시연에서는 새 버전을 등록해 배포한다.
- 띄운 직후 1분쯤은 시뮬레이터 하트비트 몇 개가 "거절"로 세어진다. 하트비트를 받을 운영 중 목록(Redis 사본)이 1분마다 다시 만들어지기 때문이다(decisions/0028).
- "이상 단말기"(오래 오프라인·배송 뒤 설치 안 됨 등)는 며칠이 지나야 걸리는 규칙이라 띄운 직후에는 없다. 시연 데이터는 시각을 고치지 않는다(decisions/0089).
- 시연 도구에는 로그인이 없다 — 묶음은 127.0.0.1에만 열린다. 다른 사람이 접속하는 서버에 그대로 올리지 않는다(decisions/0084·0087).
