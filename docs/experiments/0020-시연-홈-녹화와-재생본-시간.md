# 0020. 시연 홈 녹화와 재생본에서 걸린 시간

- 날짜 / 관련 기능: 2026-10-30 / 보강 11(decisions/0093·0094)
- 질문: 시연 홈 7막을 실제로 돌리면 기다리는 단계가 몇 초 걸리나? 녹화본은 얼마나 크고, 재생본(8배속)에서는 같은 장면이 몇 초 만에 보이나?
- 설정: 클라우드 컨테이너, 시연 묶음(`docker-compose.demo.yml`, `SWEEP_INTERVAL_MS=15000`, 시뮬레이터 하트비트 10초·오프라인 판정 90초), 매번 `down -v` → `up -d --no-build` → demo-seed `Exited (0)` 직후 녹화. Playwright 헤드리스 Chromium 1280×860. 재생본은 `npm run build:replay` → `vite preview`(:4181), 같은 Playwright
- 재현
  ```bash
  docker compose -f docker-compose.demo.yml down -v && docker compose -f docker-compose.demo.yml up -d --no-build
  # demo-seed가 Exited (0)이 된 뒤
  node apps/demo-home/scripts/record.cjs
  cd apps/demo-home && npm run build:replay && npm run preview:replay
  # 재생본 리허설 스크립트는 저장소 밖(scratchpad)에 있다 — 7막을 녹화 순서대로 누르고 기대 글이 나올 때까지 0.5초마다 본다
  ```
- 결과 — 녹화(로그의 초, 녹화 시작부터)

  | 장면 | 녹화 2(커밋 안 함) | 녹화 3(커밋한 것) |
  |---|---|---|
  | 3막 출고 → 배송 완료(DELIVERED) | 50초 | 50초 |
  | 4막 교체 출고 → 교체품 배송 완료(설치 확인 단추) | 62초 | 59초 |
  | 5막 출고 → 429 ERROR · 1번째 → 재시도 성공까지 | 32초 | 18초 |
  | 6막 정상 배포 → 완료 | 32초 | 32초 |
  | 6막 실패율 60% 배포 → 자동 중단 | 20초 | 24초 |
  | 7막 끄기 → 오프라인 판정·톡톡 알림 | 94초 | 94초 |
  | 녹화 전체 | 376초 | 364초 |
  | 응답(GET이 아닌 것) / 실행 / 사진 | 87(21) / 13 / 14 | 87(21) / 13 / 14 |

  - 녹화 1은 6막에서 멈춰 버렸다(troubleshooting/0040 — 설치한 교체품이 보고하지 않아 3단계가 10분 시간 제한까지 기다림)
  - 녹화 2는 1막 응답이 빠져 버렸다(로그인할 때 이미 읽어 두어 녹화 시작 뒤 다시 읽지 않음 → 녹화기가 시작 직후 새로 고침)
  - 녹화 3의 자동 중단 결과: "자동 중단: 2단계 실패율 25% (1/4) > 기준 20%"
- 결과 — 크기: `recording.json` 221,193바이트(녹화 3), 사진 14장 합 1.6MB(JPEG 품질 72), `public-replay` 1.8MB. 재생본 JS 335.42 kB(gzip 105.37 kB)
- 결과 — 재생본(녹화 3, 8배속): 기대 글이 보이기까지(실행을 누른 뒤)

  | 장면 | 녹화 | 재생본 |
  |---|---|---|
  | 배송 완료 | 50초 | 11.1초 |
  | 교체 접수 "끝"(설치 확인 뒤) | 59초 + 설치 | 11.1초 |
  | 429 ERROR · 1번째 | 18초 안 | 3.1초 |
  | 정상 배포 완료 | 32초 | 7.2초 |
  | 자동 중단 | 24초 | 4.0초 |
  | 오프라인 판정 | 94초 | 15.6초 |
  | 7막 전체를 누르고 "처음 상태로" → 2막 다시까지 | 364초 | 73.8초 |

  - 기대 글 14개 모두 나옴, 녹화에 없는 요청 0, pageerror 0, 390px 폭 `scrollWidth 390`, 사진 링크 `200 image/jpeg`
- 결론
  - 기다리는 단계는 재생본에서 11~16초로 줄었다. 8배라면 50초는 6.3초여야 하는데 11초다 — 결과 패널이 5초마다 다시 읽어서(POLL_MS), 시계가 지난 뒤 다음 읽기까지 최대 5초가 더 붙는다. 배속을 더 올려도 이 5초는 줄지 않는다
  - 녹화본은 GET을 바뀔 때만 남겨 응답 87개, 221KB로 Pages에 그대로 올려도 되는 크기다
- 한계
  - 녹화는 한 번에 한 흐름이다(429 재시도 횟수, 자동 중단 단계는 확률이라 녹화마다 다르다 — 18초/32초, 20초/24초)
  - 재생본 시간은 헤드리스 브라우저에서 잰 값이다. 사람이 읽는 시간은 들어 있지 않다
