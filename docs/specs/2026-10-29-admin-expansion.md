# 보강 5 설계 — 통합 어드민 확장

- 날짜: 2026-10-29
- 범위: 보강 5. 운영자 어드민(`apps/admin`)에 화면이 없던 운영자·ADMIN 단계(단말기 등록·엑셀 일괄 등록, 펌웨어 등록·단계 배포 만들기, 계정 관리)와 다른 화면 바로가기를 더하고, 그 화면에 필요한 API 하나(`GET /firmware`)를 연다. 통합 시연 준비의 네 번째 묶음이다(보강 2 로그인·역할, 보강 3 매장 화면, 보강 4 현장 화면 다음).
- 구현 계획: `docs/plans/2026-10-29-admin-expansion.md`
- 브랜치: `admin-expansion`(master 54dc512에서)
- 등장하는 회사·가맹점·제조사는 모두 가상이다. 시연 계정의 비밀번호는 `apps/api/src/db/seed-accounts.ts`의 로컬 시연 전용 값이고 이 문서에 적지 않는다.

## 1. 무엇을 왜

사용자가 원한 것은 "이 모든 것을 관리하는 어드민"이다. 시연 시나리오(발주 → 박스 스캔 입고 → 검수 → 배정·출고 → 택배 자동 수집 → 설치 → 하트비트 → 고장 접수 → 교체 출고·회수 → 펌웨어 단계 배포 → VAN 대조 → 주간 리포트)를 화면만으로 끝까지 돌려야 하는데, 지금은 몇 단계가 curl로만 된다(Day 6 남은 문제: 단말기·엑셀·펌웨어 등록과 배포 생성 화면 없음). 보강 2의 계정 API(`/admin/accounts`)와 외부 업체 키 API(`/admin/partner-keys`)도 화면이 없다.

먼저 시나리오의 단계마다 어느 앱의 어느 화면으로 되는지 점검했다(아래 2장). 이번 묶음은 그중 **운영자·ADMIN이 해야 하는데 화면이 없는 단계**를 채운다. 가상 업체·시뮬레이터·관제·개발자센터 화면은 다음 묶음(보강 6~8, 개발자센터는 7)이 맡고, 한 번에 띄우기(Docker)는 보강 9다.

목표:

1. 운영자가 단말기를 한 대 또는 엑셀로 등록하고, 행별 결과를 보고 결과를 CSV로 받는다.
2. 운영자가 펌웨어를 등록하고, 그 모델의 등록 버전을 골라 단계 배포(단계 비율·실패 임계치·최소 표본·단계 시간 제한)를 만든다.
3. ADMIN이 계정 목록을 보고 만들고, 역할을 바꾸고, 사용 중지한다(마지막 ADMIN 409 안내).
4. 어드민 왼쪽 아래 "다른 화면"에서 매장(:5174)·현장(:5175)으로 건너가고, 아직 없는 화면(관제·개발자센터·업체 콘솔·시뮬레이터)은 자리만 보인다. 주소는 한 곳(`apps/admin/src/apps.ts`)과 env.
5. 서버 규칙은 그대로 쓴다 — 이미 있는 API·DTO·검증·접근 표(기본 거부). 새 API는 꼭 필요한 하나(`GET /firmware`)만, contracts·접근 표·e2e와 함께.
6. 기존 테스트(api 568, admin 125, merchant 47, field 60, device-sim 46, partners 53)는 고치지 않는다(접근 표 한 줄, 어드민 공용 테스트 도구·쿼리 키 테스트에 한 줄씩 더하는 것만).

## 6. 결정(계획의 Task가 쓴다)

- 0066 새 API는 펌웨어 목록 하나(`GET /firmware`, OFFICE, 키셋), 요청 본문 셋·엑셀 응답에 contracts 타입
