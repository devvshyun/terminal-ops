# 보강 8 설계 — 가상 업체 콘솔과 단말기 시뮬레이터 화면

- 날짜: 2026-10-29
- 범위: 보강 8. 가상 업체 서버(`apps/partners`, :4010)와 단말기 시뮬레이터(`apps/device-sim`, :4020)를 화면에서 보고 조작하는 시연 도구 `apps/sandbox`(:5179)와 두 서버의 관리 API 보강
- 구현 계획: `docs/plans/2026-10-29-sandbox.md`
- 등장하는 회사는 모두 가상이다(세움전자·번개택배·느림보물류·브릿지VAN·톡톡메신저)

## 1. 무엇을 왜

시연에서 "택배사가 429를 낸다", "VAN이 503을 낸다", "단말기 몇 대가 꺼졌다", "펌웨어 업데이트가 30% 실패한다"를 보여 주려면 지금은 curl로 `/__admin/config`를 부른다. 업체가 무엇을 받았는지는 `/__admin/stats`의 숫자로만 보이고, 어떤 요청이 언제 왔는지는 없다. 어드민 "다른 화면"에 가상 업체 콘솔·단말기 시뮬레이터가 "준비 중"으로 있다(decisions/0067).

목표:
1. 업체마다 장애 손잡이(429·5xx 확률, 지연, 중복, 한도 등)를 화면에서 켜고 끈다. 지금 값을 서버에서 읽어 보인다
2. 업체가 받은 최근 요청(시각·업체·메서드·경로·상태·걸린 시간)과 톡톡메신저가 받은 메시지를 본다
3. 시뮬레이터를 시작·정지하고, 대수·주기·펌웨어 실패율을 바꾸고, 단말기 하나씩 끄고 켠다. 보낸 하트비트·실패·응답 시간을 본다

하지 않는 것: 로그인(decisions/0084), 브릿지VAN 등록 데이터 편집(시드 API는 그대로 — 보강 9 시연 시드에서), 업체 설정 값 검증 강화(화면이 범위를 막는다).

## 2. 구성

```
apps/partners/src/requests.ts      최근 요청 기록(메모리 고리, 200개) — 관리 API(/__admin)는 넣지 않는다
apps/partners/src/server.ts        GET /__admin/config, GET /__admin/requests?limit=
apps/device-sim/src/server.ts      GET /__admin/devices?limit=  (전체·온라인·오프라인·업데이트 중 수 + 앞에서 limit대)
apps/sandbox/                      시연 도구 화면(:5179·미리보기 4179). Vite 프록시 /partners → :4010, /sim → :4020
apps/admin/src/apps.ts             가상 업체 콘솔 http://localhost:5179/partners, 단말기 시뮬레이터 http://localhost:5179/devices
```

## 3. 관리 API(새것)

| 서버 | 엔드포인트 | 응답 |
|---|---|---|
| partners | `GET /__admin/config` | 지금 설정(`POST /__admin/config` 응답과 같은 모양) |
| partners | `GET /__admin/requests?limit=` | `{ total, items }` — 최근부터(기본 50, 최대 200). items: `id·at·partner·method·path·status·ms` |
| device-sim | `GET /__admin/devices?limit=` | `{ total, online, offline, updating, items }` — 시리얼 순 앞 limit대(기본 100, 최대 1000) |

`POST /__admin/reset`은 요청 기록도 비운다.

## 4. 화면 (`apps/sandbox`, :5179)

| 경로 | 내용 |
|---|---|
| `/partners` | 업체 다섯 카드: 손잡이(확률은 0~100% 슬라이더, 지연은 ms), 바꾸면 그 업체 값만 보낸다. "모두 기본값으로"(reset, 데이터도 비운다는 확인). 아래에 최근 요청 표(5초마다 새로 읽기, 업체 고르기)·톡톡 메시지 |
| `/devices` | 시작·정지, 설정(대수·시리얼 앞글자·주기·묶음·펌웨어 실패율·대상 api 주소), 통계(주기·보낸·받아들인·거절·실패·p50/p95), 단말기 표(온라인/오프라인 단추 — `offlineSerials`를 바꾼다) |

## 5. 검증
- partners·device-sim: 새 관리 API 테스트(기록에 관리 API가 안 들어감, 최근부터, limit, reset이 비움, 목록 수)
- 화면: Vitest(손잡이 → 그 업체만 보냄, 요청 표, reset 확인, 시작·정지, 단말기 끄기 → offlineSerials, 서버가 안 떠 있으면 안내), build
- 실서버: partners·device-sim·api를 띄우고 화면에서 번개 429 켜기 → 요청 표에 429, 단말기 하나 끄기 → 다음 주기에 그 단말기 하트비트 없음
