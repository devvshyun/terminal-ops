# 0021. 이미 목표 버전인 대상이 시간 초과로 세져 같은 버전 재배포가 자동 중단됨

- 날짜 / 관련 기능: 2026-10-23 / F8 (Day 4 최종 리뷰)
- 증상(리뷰 지적, 코드 읽기): 배포 대상 중 이미 그 버전을 돌리는 단말기가 있으면, 그 단말기는 결과를 보고하지 않는다. 제한 시간이 지나면 TIMED_OUT(실패)으로 세져 실패율이 오르고, 같은 버전을 다시 배포하면 자동 중단까지 간다.
- 가설: 세 규칙이 겹쳤다. ① 대상 선정은 지금 버전을 보지 않는다(decisions/0030, "이미 그 버전인 단말기도 대상이 된다"). ② 하트비트는 보낸 버전이 제안 버전과 같으면 `update`를 싣지 않는다(Task 7 리뷰, `heartbeat.service.ts`). ③ device-sim도 이미 그 버전이면 지시를 무시한다(`fleet.ts` `startUpdate`). → 보고가 오지 않고, 판단은 제한 시간이 지난 OFFERED를 모두 TIMED_OUT으로 바꾼다.
- 확인(테스트 먼저): `apps/api/test/firmware-control.e2e.spec.ts` '하트비트로 이미 목표 버전을 보낸 대상은…'. 단계 [10, 100](대상 2대), 기준 20%, minSamples 1, 제한 시간 1초. 1대는 하트비트로 목표 버전을 보냄(응답에 `update` 없음 확인), 1대는 성공 보고. `control(id, now + 2초)`.
  - 고치기 전 결과: `expected ADVANCED, stage 1, timedOut 0` 대신 `"action": "ABORTED"`, `"stage": 0`, `"timedOut": 1`. 실패율 1/2 = 50% > 20%로 거짓 자동 중단. 리뷰 분석이 맞았다.
  - 같이 쓴 Minor 테스트 2개도 먼저 실패: 제안 내리기 Lua가 깨진 값 하나에 `ReplyError: ERR user_script:5: Expected object key string but found invalid token`, `finishedAt`이 `control(id, now)`의 now가 아니라 실제 시각(`expected 1792758714000 to be 1792762314000`). → `Tests 3 failed | 1 passed`
- 원인: decisions/0030은 "이미 그 버전이면 업데이트 없이 성공 보고하면 된다"를 전제로 대상에서 빼지 않았다. Task 7 리뷰에서 하트비트가 그 경우 지시를 싣지 않게 바꾸면서 이 전제가 깨졌는데, 판단 쪽은 그대로였다.
- 해결(이 커밋): `RolloutService.control`이 제한 시간이 지난 운영 중 대상의 Redis `hb:fw`를 HMGET으로 읽어, 목표 버전이면 SUCCEEDED(reported_version 목표 버전, reported_at = 판단 시각)로, 나머지만 TIMED_OUT으로 바꾼다. 둘 다 PK + `status='OFFERED'` 조건이고, 바뀐 행 수의 합이 고른 수보다 적으면 이번 주기는 WAITING(troubleshooting/0019의 규칙 그대로). 결과의 `timedOut`은 TIMED_OUT만 센다. 단계 진입 때 빼는 방식은 고르지 않았다(decisions/0031). Minor: 제안 내리기 Lua를 `pcall(cjson.decode, v)` + `type(o) == 'table'`로, `finish`는 판단의 now를 쓴다.
  - 고친 뒤: 새 테스트 4개 포함 펌웨어 두 파일 `Tests 27 passed (27)`, typecheck exit 0. 전체 결과는 devlog 2026-10-23 최종 리뷰 fix 항목.
- 남는 것: 이미 목표 버전인 대상은 단계 제한 시간(기본 10분)이 지나야 성공으로 세진다. 하트비트 버전을 믿으므로 거짓 버전을 보내는 단말기는 성공으로 세진다(단말기 인증 없음).
- 배운 것: 한쪽에서 "보낼 필요 없는 지시는 생략"하면, 그 지시에 대한 응답을 기다리는 쪽은 "응답이 오지 않는 정상 상태"를 따로 다뤄야 한다. 전제를 깬 수정은 그 전제를 적은 결정 기록부터 다시 읽는다.
