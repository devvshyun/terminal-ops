# 0024. Bash heredoc 안의 파이썬 편집 스크립트가 따옴표 오류로 돌지 않음(도구 사용 문제)

- 날짜 / 관련 기능: 2026-10-26 / 없음(작업 도구). devlog 2026-10-26의 12:20·12:42·13:10·14:34·Task 11 항목
- 증상: 파일을 고치려고 Bash 도구 명령 하나에 heredoc으로 파이썬 스크립트를 넣어 실행했는데, 셸이 파이썬을 부르기 전에 `unexpected EOF while looking for matching` 오류로 끝났다. 하루에 여섯 번(12:20 한 번, 12:42 두 번, 13:10 한 번, 14:34 두 번), Task 11에서 한 번 더(아래 보탬). 파일은 바뀌지 않았고(파이썬이 돌지 않음), 매번 스크립트를 파일로 써서 실행하거나 Edit 도구로 다시 했다. 그때는 "코드 문제가 아니다"라며 devlog에만 적었는데, 같은 일이 되풀이돼 원인을 적어 둔다(Task 8 리뷰 지적).
- 가설:
  1. heredoc 구분자를 따옴표 없이 써서(`<<PY`) 본문의 `$`·백틱을 셸이 먼저 풀었다.
  2. 명령 전체를 작은따옴표로 한 번 더 감싼 곳(`bash -c '…'`, `sh -c '…'`, `node -e '…'` 안의 heredoc)에서 본문의 작은따옴표(파이썬 문자열의 `'`, 한글 문장 속 `it's` 같은 것)가 바깥 따옴표를 닫았다.
  3. CRLF가 섞인 heredoc 끝 줄을 구분자로 알아보지 못했다.
  4. (보탬에서 더함) 우리 명령이 아니라 Bash 도구가 명령 글자를 `bash -c`에 넘기는 단계에서 따옴표가 깨진다.
- 확인(2026-10-26 Task 11, Git Bash `GNU bash, version 5.2.37(1)-release (x86_64-pc-msys)`, 스크래치패드에서 재현):
  - 구분자에 따옴표가 있고 바깥 감싸기가 없으면(`x=$(python - <<'PY'` … `print("it's")` … `PY`) 정상: `[it's]`, exit 0.
  - 따옴표 없는 구분자(`<<PY`)에 백틱이 있으면 셸이 명령 치환을 해 `x: command not found` — 오류 종류가 다르고 exit 0(조용히 틀린 내용으로 돈다).
  - 바깥 작은따옴표 안의 heredoc(`bash -c 'python - <<PY` / `s = "it's"` / …)은 `t3.sh: line 2: unexpected EOF while looking for matching '"'`, exit 2 — 기록된 증상과 같은 메시지.
  - 원래 실패한 명령 글자는 남기지 않아 다시 볼 수 없다. 그래서 "원래 명령이 2였다"는 같은 오류 메시지를 재현한 데서 나온 추정이다.
- 보탬(Task 11 마감, 같은 날 15시대): 이 기록을 쓴 뒤 devlog 요약(약 120줄, 백틱·작은따옴표·`* * *`가 섞인 한국어 글)을 `cat >> 파일 <<'EOF'`(구분자 따옴표 있음, 바깥 감싸기 없음 — 아래 해결 ②를 지킨 모양)로 덧붙이려던 Bash 도구 명령이 `/usr/bin/bash: -c: line 46: unexpected EOF while looking for matching` + 작은따옴표로 또 실패했다(파일은 그대로 — `git status`·`tail`로 확인).
  - 같은 글을 Write 도구로 파일에 쓰고, 그 파일로 `cat > /dev/null <<'EOF'` … `EOF` 스크립트를 만들어 `bash -n` → 문법 통과(`parse-ok`), `bash -c "$(cat 스크립트)"`도 정상 실행(`whole-ok`). 즉 **같은 글자를 bash에 직접 주면 문제가 없다**(Write로 옮기며 백슬래시 섞인 따옴표 두 곳만 글자를 바꿨다).
  - 의심 줄(오류가 말한 46번째 줄 — 작은따옴표가 든 줄)만, 그리고 백슬래시 + 작은따옴표 한 줄만 heredoc으로 Bash 도구에 보낸 명령은 둘 다 정상이었다. 어느 글자 조합이 문제인지는 더 나누지 않았다.
  - 그래서 이번 건은 가설 2(우리 명령의 바깥 작은따옴표)가 아니다. 오류 머리 `/usr/bin/bash: -c:`로 보아 가설 4로 **추정**한다(도구 내부는 보지 못함). 앞의 여섯 번도 같은 원인이었을 수 있다.
- 원인(추정): 2 또는 4. 2는 같은 메시지를 재현했고, 4는 "같은 글자가 bash에서는 정상"까지만 확인했다. 3은 이번에 재현하지 않았다(Day 3의 `\r` 문제 devlog 2026-10-23은 파이썬 글자 안의 `\r`이 CR로 들어간 다른 일).
- 해결(작업 방식): ① 여러 줄 파이썬 편집은 스크립트를 파일로 쓰고 경로로 실행한다, ② heredoc을 쓰면 구분자를 늘 따옴표로 감싸고(`<<'EOF'`) 바깥을 다시 작은따옴표로 감싸지 않는다, ③ 정확한 여러 줄 바꾸기는 Edit 도구를 쓴다, ④ 따옴표·백틱이 섞인 긴 글(기록)을 덧붙일 때는 Write 도구로 임시 파일에 쓰고 `cat 임시파일 >> 대상`으로 붙인다(Task 11 요약은 이렇게 붙였다). 코드는 바뀐 것이 없다.
