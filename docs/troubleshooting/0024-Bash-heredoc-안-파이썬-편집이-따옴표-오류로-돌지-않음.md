# 0024. Bash heredoc 안의 파이썬 편집 스크립트가 따옴표 오류로 돌지 않음(도구 사용 문제)

- 날짜 / 관련 기능: 2026-10-26 / 없음(작업 도구). devlog 2026-10-26의 12:21·12:42·13:10·14:34 항목
- 증상: 파일을 고치려고 Bash 도구 명령 하나에 heredoc으로 파이썬 스크립트를 넣어 실행했는데, 셸이 파이썬을 부르기 전에 `unexpected EOF while looking for matching` 오류로 끝났다. 하루에 여섯 번(12:21 한 번, 12:42 두 번, 13:10 한 번, 14:34 두 번). 파일은 바뀌지 않았고(파이썬이 돌지 않음), 매번 스크립트를 파일로 써서 실행하거나 Edit 도구로 다시 했다. 그때는 "코드 문제가 아니다"라며 devlog에만 적었는데, 같은 일이 되풀이돼 원인을 적어 둔다(Task 8 리뷰 지적).
- 가설:
  1. heredoc 구분자를 따옴표 없이 써서(`<<PY`) 본문의 `$`·백틱을 셸이 먼저 풀었다.
  2. 명령 전체를 작은따옴표로 한 번 더 감싼 곳(`bash -c '…'`, `sh -c '…'`, `node -e '…'` 안의 heredoc)에서 본문의 작은따옴표(파이썬 문자열의 `'`, 한글 문장 속 `it's` 같은 것)가 바깥 따옴표를 닫았다.
  3. CRLF가 섞인 heredoc 끝 줄을 구분자로 알아보지 못했다.
- 확인(2026-10-26 Task 11, Git Bash `GNU bash, version 5.2.37(1)-release (x86_64-pc-msys)`, 스크래치패드에서 재현):
  - 구분자에 따옴표가 있고 바깥 감싸기가 없으면(`x=$(python - <<'PY'` … `print("it's")` … `PY`) 정상: `[it's]`, exit 0.
  - 따옴표 없는 구분자(`<<PY`)에 백틱이 있으면 셸이 명령 치환을 해 `x: command not found` — 오류 종류가 다르고 exit 0(조용히 틀린 내용으로 돈다).
  - 바깥 작은따옴표 안의 heredoc(`bash -c 'python - <<PY` / `s = "it's"` / …)은 `t3.sh: line 2: unexpected EOF while looking for matching '"'`, exit 2 — 기록된 증상과 같은 메시지.
  - 원래 실패한 명령 글자는 남기지 않아 다시 볼 수 없다. 그래서 "원래 명령이 2였다"는 같은 오류 메시지를 재현한 데서 나온 추정이다.
- 원인(추정, 위 재현으로 같은 메시지 확인): 2. 바깥 작은따옴표 안에서 본문의 작은따옴표가 따옴표 짝을 깨, 셸이 명령 끝까지 짝을 찾다 EOF를 만난다. 3은 이번에 재현하지 않았다(Day 3의 `\r` 문제 devlog 2026-10-23은 파이썬 글자 안의 `\r`이 CR로 들어간 다른 일).
- 해결(작업 방식): ① 여러 줄 파이썬 편집은 스크립트를 파일로 쓰고 경로로 실행한다, ② heredoc을 쓰면 구분자를 늘 따옴표로 감싸고(`<<'EOF'`) 바깥을 다시 작은따옴표로 감싸지 않는다, ③ 정확한 여러 줄 바꾸기는 Edit 도구를 쓴다. 코드는 바뀐 것이 없다.
