# 0032. 테스트 DB로 마이그레이션을 적용하면 DB 이름의 스냅샷 파일이 생긴다

- 날짜 / 관련 기능: 2026-10-28 / 보강 2 마감(Task 7 실서버 확인)
- 증상: 실서버 확인 준비로 테스트 DB에 `MYSQL_DATABASE=terminal_ops_test node dist/db/migrate.js up`과 `node dist/db/seed.js`를 돌린 뒤 `git status --short`에 `?? apps/api/src/migrations/.snapshot-terminal_ops_test.json`(128,530바이트)이 나타났다. 기준 스냅샷은 `.snapshot-terminal_ops.json`(개발 DB 이름) 하나다.
- 가설: 1) api 테스트(vitest)가 만든다 2) `migrate.js up`이 지금 DB 이름으로 스냅샷을 쓴다 3) 시드가 쓴다
- 확인: 파일을 지우고 테스트 DB를 다시 만든 뒤 `MYSQL_DATABASE=terminal_ops_test node dist/db/migrate.js up`만 돌리자 파일이 다시 생겼다 → 2. 그 뒤 시드를 돌려도 그대로(3은 확인 못 함 — 이미 있어서). 테스트 코드에는 migrator·snapshot을 부르는 곳이 없다(`grep -rln "migrator\|checkSchema" test` — 실험 파일만, 실험은 이번에 돌리지 않음) → 1 기각. MikroORM 설정(`mikro-orm.config.ts`)에 스냅샷 이름 지정이 없어 기본값(`.snapshot-<DB 이름>.json`)을 쓴다. `up`이 스냅샷을 쓰는 정확한 시점(초기화인지 적용 뒤인지)은 MikroORM 소스로 확인하지 않았다(추측: 적용 뒤 스냅샷 갱신).
- 원인: 스냅샷 파일 이름이 접속한 DB 이름을 따른다. 계획 사전 검증이 `.snapshot-terminal_ops.json`을 `_test` 이름으로 복사해 쓴 것과 같은 이유.
- 해결: 생긴 파일을 지웠다(커밋하지 않음). 같은 일을 다시 해도 커밋에 섞이지 않게 저장소 `.gitignore`에 이 파일 이름을 더했다. 개발 DB 스냅샷(`db:migration:create`가 비교에 쓰는 것)은 그대로다.
- 배운 것: 테스트 DB에 스키마를 올릴 때는 `migrate.js up`보다 테스트가 쓰는 `resetDatabase`(schema refresh)가 부작용이 적다. 실서버 확인처럼 마이그레이션 경로 자체를 보고 싶을 때만 `up`을 쓰고 `git status`를 본다.
