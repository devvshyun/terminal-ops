# 0034. 좁은 화면에서 표를 옆으로 밀게 했는데도 문서 폭이 늘어난다

- 날짜 / 관련 기능: 2026-10-29 / 개발자센터(`apps/developers`, decisions/0080)
- 증상: 390px 폭에서 표가 글자마다 줄을 바꿨다(키 접두사 `pk_35ffdbee`가 세로로 한 글자씩). 표를 `display: block; overflow-x: auto; white-space: nowrap`으로 바꾼 뒤에도 업체 화면 `document.documentElement.scrollWidth`가 637(목표 390), 문서 화면이 449였다
- 가설: 1) 처음 증상은 내가 넣은 `body { overflow-wrap: anywhere }` 때문 2) 표가 든 격자 칸(`.split`)이 표만큼 늘어난다 3) 표 밖으로 나가는 다른 요소
- 확인(Playwright, 390×844, 요소마다 `getBoundingClientRect().right > 391`와 `scrollWidth > 395`를 셌다):
  - 1: `overflow-wrap: anywhere`를 빼자 글자마다 끊기던 것은 사라졌다 → 맞음. `word-break: keep-all`만 남겼다
  - 2: 표 두 개의 계산된 스타일은 `block auto`, 바깥 상자는 L33~R357(화면 안) → 격자 칸이 늘지는 않았다. `.split > * { min-width: 0 }`은 넣어 두었다(격자 칸 기본 `min-width: auto`가 내용만큼 늘 수 있어서)
  - 3: 표 밖 요소 중 폭을 넘는 것이 없는데 `HTML sw637`. 남은 후보는 표 안에서 표의 스크롤에 갇히지 않는 요소 — 키 표 마지막 머리칸의 `<span className="sr-only">작업</span>`(`position: absolute`). absolute 요소는 가장 가까운 positioned 조상을 기준으로 하는데 그런 조상이 없어 문서(초기 포함 블록)에 붙고, 정적 위치(옆으로 밀린 표의 오른쪽 끝, x≈630)에 놓여 문서 폭을 늘렸다. `table { position: relative }`를 넣자 업체 화면 390 → 맞음
  - 문서 화면 449는 다른 원인: 경로 제목 `GET /partner/v1/merchants/{merchantCode}/terminals`(고정폭)가 `keep-all` 때문에 줄을 못 바꿔 `H2 sw414`. `.op h2 { overflow-wrap: anywhere }`로 390
- 원인: 스크롤 상자(`overflow: auto`)는 positioned가 아니면 absolute 자손을 가두지 못한다. 그리고 `keep-all`은 공백 없는 긴 영문 경로도 끊지 않는다
- 해결: `table { position: relative }`, 경로 제목에만 `overflow-wrap: anywhere`, body에는 `word-break: keep-all`만. 네 화면 모두 390에서 `scrollWidth 390`
- 배운 것: 숨김 글(`.sr-only`)도 레이아웃에 자리를 갖는다 — absolute의 기준 상자를 정해 둔다 → study/backlog.md

### 보탬 (시연 도구, 2026-10-29)
- `apps/sandbox` 단말기 화면이 390px에서 `scrollWidth 458`. 이번 원인은 설정 폼의 두 칸 줄(`grid-template-columns: 1fr 1fr`) — `1fr`의 최소 폭이 `auto`라 입력칸의 기본 폭(약 170px)이 칸을 밀었다. `minmax(0, 1fr)`과 폼 입력 `width: 100%; min-width: 0`으로 390
