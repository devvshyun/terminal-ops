# 0036. 시연 데이터 진행 줄과 마지막 요약의 개수가 다르다

- 날짜 / 관련 기능: 2026-10-30 / 보강 9(시연 데이터, decisions/0089)
- 증상(로컬 컨트롤러 리허설, 받아 적은 것): `demo-seed` 로그 진행 줄 "재고 3 · 입고 2 · 배정 1 · 배송 중 2", 마지막 줄 `시연 데이터 완료: {"inStock":2,"shipping":2,…}`, 어드민 화면은 재고 2 · 배송 중 3(DM-0013·0019·0020). 세 곳이 서로 다르다.
- 가설: 1) 시드가 단말기를 덜·더 만든다 2) 개수를 세는 시점이 다르다(교체 출고 앞뒤) 3) 요약이 일부만 고쳐졌다
- 확인: `apps/api/src/db/scenario.ts`를 읽음 — 진행 줄은 2) 단계 끝(A/S 전)에 `inStock.length`(3)·`shipping.length`(2)를 찍는다. 3) A/S 단계가 재고 첫 대 DM-0013을 교체품으로 출고해 재고 → 배송 중으로 옮긴다. 요약은 `inStock.length - 1`(교체품 반영)인데 `shipping.length`(2)는 그대로였다. e2e의 단말기 상태 검사(13 SHIPPED, 14·15 IN_STOCK, 19·20 SHIPPED)는 원래 통과 → 가설 1 기각, 2·3 확인. 테스트에 요약·진행 줄 기대를 먼저 넣어 돌림: `- "shipping": 3, + "shipping": 2`, `Tests  1 failed | 2 passed (3)`
- 원인: 진행 줄은 교체 출고 전에, 요약은 반만 고친 식으로 세었다. 데이터 자체는 맞다(어드민 화면이 맞다).
- 해결: 교체 출고 뒤에 `counts`를 한 번 세어 진행 줄과 요약이 같은 값을 쓴다 — "재고 2 · 입고 2 · 배정 1 · 배송 중 3(교체품 포함)". e2e 3/3 통과, 시연 묶음을 다시 띄워 로그 두 줄이 같음을 확인(devlog 2026-10-30). 커밋 = 이 기록이 든 커밋
- 배운 것: 요약 숫자는 데이터를 바꾸는 마지막 단계 뒤에 한 번만 센다. 사람이 읽는 로그도 테스트로 지킨다.
