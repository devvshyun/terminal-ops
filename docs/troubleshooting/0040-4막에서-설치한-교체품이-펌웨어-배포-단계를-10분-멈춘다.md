# 0040. 4막에서 설치한 교체품이 펌웨어 배포 단계를 10분 멈춘다

- 날짜 / 관련 기능: 2026-10-30 / 보강 11(녹화), 시연 홈 6막, F11 펌웨어 배포
- 증상: 첫 녹화에서 6막 "정상 배포"(SN-100 1.2.0)가 "· 완료"를 내지 않았다. 녹화 로그의 마지막 줄은 `[ 191s] 실행 6-ok "SN-100 새 버전 배포" → 1.2.0 배포 시작`. 보강 10 리허설에서는 같은 단계가 25초 만에 끝났다
- 가설
  1. 실패율 손잡이가 남아 있다(5막 뒤 정리 누락)
  2. 배포 대상 가운데 보고하지 않는 단말기가 있다
  3. 워커가 멈췄다
- 확인
  - `select * from firmware_rollout` → #2 SN-100 `RUNNING`, `current_stage: 2`(3단계, 100%), `stage_timeout_ms: 600000`
  - 대상 상태별 수: 1단계 성공 2, 2단계 성공 4, 3단계 성공 4·**OFFERED 1** → 한 대만 보고가 없다. 1·2단계가 성공으로 넘어갔으니 워커와 실패율은 정상이다 → 가설 1·3 기각
  - 그 대상의 `terminal_id: 14` → `DM-0014` `IN_SERVICE`. 4막에서 점주가 설치를 확인한 교체품이다
  - 시뮬레이터 `GET /__admin/config`의 `serials`에 `DM-0014`가 없다(시연 데이터의 13대뿐) → 가설 2 확인
- 원인: 배포는 운영 중(IN_SERVICE)인 그 모델 단말기를 대상으로 고른다. 시뮬레이터는 띄울 때 받은 단말기 목록만 하트비트를 보낸다. 4막에서 교체품을 설치하면 운영 중이 되지만 시뮬레이터 목록에는 없어, 마지막 단계가 시간 제한(10분)까지 기다린다. 보강 10 리허설은 설치 확인을 건너뛰어(교체품이 배송 완료에 머묾) 드러나지 않았다. api 규칙의 잘못은 아니다 — 실제로는 설치한 단말기가 켜져 하트비트를 보낸다. 시연 환경이 그 일을 하지 않은 것이다
- 해결: 시연 홈의 배포 실행(`startRollout`)이 배포를 만들기 전에 `powerOnInService(modelCode)`를 부른다. 운영 중인데 시뮬레이터가 모르는 단말기를 시뮬레이터 `serials`에 더한다("켠다"). 시뮬레이터가 목록이 아니라 개수로 단말기를 만드는 모드(`serials` 빈 배열)면 건드리지 않는다. 테스트를 먼저 써서 `Tests  1 failed | 10 passed (11)` → 구현 → 54개 모두 통과. 고친 web 이미지로 처음부터 다시 녹화했다
- 남은 것: 어드민 "펌웨어 배포"에서 직접 배포를 만들면 이 보정을 거치지 않는다(시연 홈 밖). 시뮬레이터가 api의 운영 중 단말기를 스스로 따라가게 하는 것은 범위 밖으로 둔다
- 배운 것: 리허설에서 건너뛴 단계(설치 확인)가 뒤 막의 전제를 바꿨다. 녹화처럼 "전부 실제로"를 하면 리허설이 못 본 연결이 드러난다
